## 一、使用规则

> **纪律**：本册是 Phase 0 风险的**唯一登记处**。任何报告中出现的风险编号，必须能在本册找到对应行；本册中任何一行，必须能追溯到明确来源。

### 1.1 编号与生命周期规则

| # | 规则 |
|---|---|
| 1 | **编号一经分配不得复用**。风险关闭后**保留行不删除**，仅在「状态」列标注「已关闭」，并保留关闭依据。 |
| 2 | **每条风险必须能追溯到「来源」**（哪个报告 / 哪天的日报 / 上游计划哪一节）。无来源的风险条目不得进入本册。 |
| 3 | **「已触发」的风险必须给出具体处置动作**，不得写"注意一下""密切关注"这类泛泛表述；处置动作须具体到可执行步骤与产出物落点。 |
| 4 | 状态取值**四选一**：`潜在` / `已触发` / `已关闭` / `已降级为已知缺陷`（后者须给出 `docs/known-issues.md` 的 ISS 编号）。禁止留空、禁止写"待观察"。 |
| 5 | 实例化风险（§三）与主风险册（§二）之间必须建立**双向引用**：实例化行标注其对应的主风险编号，主风险行的「剩余风险」中说明实例化情况。 |
| 6 | 与 `docs/known-issues.md` 的联动：**「需换方案」状态的缺陷必须同时出现在本册**（见 §五）。 |
| 7 | 本册在 P0 结束时随 `docs/handover-p1.md` 移交；未关闭项自动成为 P1 遗留风险。 |

### 1.2 概率档位判定标准

| 档位 | 判定标准 |
|---|---|
| **高** | 在 Phase 0 剩余工期内**很可能发生**（≥50% 把握）；或**已经发生**（含"已实测确认"）。 |
| **中** | 有明确发生条件，但**是否发生取决于尚未做出的决策或未完成的外部动作**（如用户择机执行、第三方口径、待定选型）。 |
| **低** | 已有确定且经过验证的规避手段，或在当前约束下**发生路径已被阻断**。 |

### 1.3 影响档位判定标准

| 档位 | 判定标准 |
|---|---|
| **高** | 使某验证项**无法开展或结论无效**；或**推翻整条技术路线 / 组件选型**；或违反核心保证（不丢状态、不重复副作用、不编造数字）。 |
| **中** | 结论仍可得出，但**可信度显著下降**，或需**重跑全部实验**，或需**追加工期**。 |
| **低** | 有影响但**有明确规避手段**且规避后不影响结论有效性；或影响局限于单次实验的可追溯性。 |

> **纪律**：概率与影响是**判断**而非实测数字，不得伪装成实测值。凡涉及实测数字的表述，一律写 `【待 D<天> 实测填入】`。

|---|---|
| 1 | **每条缺陷必须指定是否已登记到本册**（`docs/known-issues.md` §一 规则 3）。本册 §3.6 / §3.7 即为其落点。 |

| 5 | 缺陷编号一经分配**不得复用**；缺陷关闭后**保留行**，本册风险行同样保留。 |
