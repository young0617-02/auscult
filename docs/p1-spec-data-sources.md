## 一、盘点目的与使用方式

本文件回答三个问题，供 V6（范围锁定）与 V7（评测集构建）直接引用：

1. **有哪些数据可以用**？（逐类盘点表）
2. **拿不到或不能用时怎么办**？（兜底路线：默认自编模拟数据）
3. **谁负责、走什么渠道、什么优先级**？（采集优先级 + 联系人/渠道占位）

> **纪律**：本清单中凡"可用性判定 = 需确认"的类别，**不得**在 P1 未闭环前作为知识库正式语料入库；仅可用于本阶段的模拟替身。

## 三、兜底路线（**默认自编模拟数据**）

> **决策**：本阶段及 Phase 1 的**默认数据来源是自编模拟数据**。真实数据"能拿到就是加分项，拿不到不阻塞主线"。
> **理由**：版权/隐私判定是**唯一不可控的外部依赖**（见 §四），不能让它卡住 10 个工作日的关键路径。

### 3.1 模拟数据生成方式

| 类别 | 生成方式 | 目标规模 | 生成工具/脚本（P1 落 `scripts/`，本阶段只需规格） |
|---|---|---|---|
| 传感器时序 | Sparkplug B 模拟器：按 `spBv1.0/<group>/DDATA/<node>/<device>` 周期发布，振动用**正弦基频 + 工频谐波 + 随机噪声 + 注入轴承特征频率（BPFO/BPFI/BSF/FTF）**叠加，异常段幅值随时间线性爬升 | 3 设备 × 3 测点 × 1Hz × **30 天** ≈ 2,300 万点（可裁剪至 7 天做首轮） | `scripts/sim_sparkplug.py`（P1 编写；**等价能力已由 `scripts/spb_simulator.py` 实现并自检测试通过**） |
| 告警事件 | 由时序数据按阈值规则（振动 RMS 阈值 + 滑动窗口 Z-Score）**离线回放生成**，保证告警与原始曲线可对应 | 200–500 条告警 | `scripts/sim_alarm_replay.py`（P1；**告警回放已由 `scripts/run_v3_alert.py` 实现**，阈值+滑动窗口 Must#1/#2 已 PASS） |
| 设备手册 | 按真实手册的**章节骨架**（安全须知/结构原理/安装/运行/维护/故障排查/备件）自撰内容，术语取自公开工业文本 | **6 册 × 约 120 页**，切块后约 **1,500–2,500 块** | 人工撰写 + 模板（P1） |
| 维修工单 | 按真实 CMMS 字段结构生成，姓名/客户号/联系方式**全部伪造**，故障现象与 §3.1 时序异常段对应 | **300 条** | 人工 + 脚本填充（P1） |
| 故障案例 | 按公开故障机理（不平衡/不对中/轴承磨损/气蚀/松动）编写，每篇含现象—分析—处置—结论 | **40 篇** | 人工撰写（P1） |
| 标准判据 | 从公开工程常识整理**判据表**（振动烈度区间 → 设备状态），不复制标准原文 | 1 份判据表 | 人工整理（P1） |
| 拓扑图纸 | 虚构厂区，5 台泵 + 管路 + 传感器点位，导出为结构化三元组（供 Neo4j）与图片（供前端） | **5 台设备 / 约 120 条三元组** | 人工 + Cypher 导入（P1） |

### 3.2 模拟数据的**强制约束**

1. **可复现**：所有模拟数据必须由**固定 seed** 生成，seed 记入实验登记（见 `docs/prj-template-experiment-log.md`）；
2. **可区分**：所有模拟数据文件与元数据中必须带 `synthetic: true` 标记，**禁止与真实数据混放同一目录**；
3. **可替换**：模拟数据结构须与真实数据**字段级等价**，使得未来换取真实数据时无需改代码，只需换数据源；
4. **不冒充**：模拟数据**不得**在报告中以"现场数据"表述。

### 3.3 局限声明（**必须随每份报告出现**）

> **局限声明（固定文本，不得删改）**：
> 本阶段所有质量类结论（`Recall@5`、`MRR`、`NDCG@5`、引用正确率、幻觉率、置信度 ECE 等）均**基于模拟数据的初步验证**，语料由项目组自编，其分布、术语密度与真实现场资料存在差异。因此上述指标**仅证明"链路可运行、方案可比较"，不等于现场可用性结论**。Phase 1 取得真实语料后，须以同一评测集与同一流程**重测**并对齐本结论。

## 四、版权 / 隐私判定延迟的应对（**唯一不可控外部依赖**）

| 项 | 内容 |
|---|---|
| **风险编号** | R15（见 `docs/prj-ledger-risk-register.md`） |
| **性质** | 依赖外部（客户法务 / 厂商授权 / 客户 IT）回复，**工期不可控** |
| **触发条件** | 任一"需确认"类别在 D1 后 5 个工作日内未取得书面回复 |
| **应对策略** | ① **不等待**：D1 起即以模拟数据推进全部验证项；② **双轨并行**：模拟数据用于打通链路，真实数据仅用于最终重测；③ **最小化依赖**：标准规范改为"仅引用条款编号 + 自编判据表"，绕开版权；④ **脱敏前置**：工单/案例在拿到当日即脱敏，不等审批 |
| **责任边界** | 版权判定由**数据提供方**出具书面结论；本项目组**不自行推定**为可用 |
| **兜底结论** | 若至 **D10 仍无书面回复**：V6 判定为**中间区间**（"需自编 → 模拟数据交付并标注局限"），按 `docs/p0-spec-gate-criteria.md` 记录处置动作与指标代价，**不阻塞 M0.6** |
| **升级路径** | D10 后仍未闭环 → 写入 `docs/p0-handover-p1.md`，作为 **P1 首日遗留问题** |
