## 三、判据（Pass / 中间 / No-Go）—— **D1 定稿，开跑前已就位**

| 档位 | 阈值 | 含义 | 后续动作 |
|---|---|---|---|
| **Pass** | **首次成功率 ≥ 90%** 且 **参数可解析率 ≥ 95%** | 本地模型可直接承担该角色 | 直接采用；写入 §六 结论表 |
| **中间** | **首次成功率 70%–90%** | 可用但需加固 | **必须**按 §四 执行处置动作；**中间 ≠ 通过** |
| **No-Go** | **首次成功率 < 70%**（两模型均如此时触发全局 No-Go） | 本地模型不可承担该角色 | 转"本地推理 + 云端工具调用"混合形态，或该角色直接交给云端 |

> ⚠️ **分档重校（2026-09-28 起为权威口径）**：上表是**单线全局口径**（保留作整体下界参考）。
> 只报全局首次成功率会掩盖"类型间差异极大"的事实（实测本地：多工具 **0.00**、单工具 0.33–0.39）。
> 故 V1 判据已改为**按用例类型分档**（`docs/p0-spec-gate-criteria.md` §3.1.1），实现见
> `scripts/judge_tools.py` 的 `TIER_CRITERIA` 与 `judge_verdict_tiered`：
> 单工具 / 参数校验 / 多轮 pass 0.85、无效拒绝 pass 0.90、**多工具 pass 0.70（中间 0.50–0.70）**；
> **整体档位 = 有数据类型的最差档位**。本表与 §四 流程保留作降级路径索引。

### 3.1 判据细则

| 项 | 规定 |
|---|---|
| 主判据口径 | **首次成功率**（第 1 次即全对）；重试后成功率仅作参考，**不得**用于判定 Pass |
| 样本量 | 20 用例 × 3 次 = 60 次调用/模型；**单次百分比粒度 1.67%**，报告中须同时给出分子/分母（如 17/20） |
| 可解析率口径 | `think` 剥离**之后**再判 JSON；剥离前的失败**不计入**可解析率，但须单独统计为"think 污染率" |
| 拒绝率口径 | "应拒绝却调用"与"应调用却拒绝"**分开报**，不得合成一个数字 |
| 模型对照 | 两个本地模型用**同一套用例、同一提示词版本、同一 `num_ctx`/`temperature`**（`temperature=0.0`、`num_ctx=8192`） |
| 判据对照 | 结论中必须写明"对照的是哪一档"（Pass/中间/No-Go） |

## 四、中间区间（70%–90%）处置动作（**必须写全，按顺序执行**）

> 触发条件：某角色首次成功率落入 **70%–90%**。
> 执行顺序：**① → ② → ③ → ④**，逐级加固；每级都须**重跑同一套 20 用例**并留痕（新开 `experiment_id`）。

### 4.1 ① 约束解码（Constrained Decoding，**实际载体 = JSON Schema**）

| 项 | 内容 |
|---|---|
| 手段 | 用 llama.cpp 的 **GBNF 文法**或等价约束解码机制，把输出**强制限定为 Tool Schema v1 的合法 JSON** |
| 预期收益 | 直接拉高"参数 JSON 可解析率"；对"参数值正确率"有间接收益 |
| 代价 | ① 需引入约束层，增加工程复杂度；② 可能**轻微增加延迟**（须实测并记录 P95 变化）；③ 文法须与 Schema v1 同步维护，**Schema 升版则文法必须升版** |
| 留痕要求 | 记录约束前后的：首次成功率、可解析率、P95 延迟 |
| 判据代价标注 | 若引入约束解码，须在报告中标注对 **`P95`** 的影响 |

> **实现载体实证更新（2026-09-24 第二轮）**：Ollama 0.34.2 **拒绝原始 GBNF 字符串**
> （`/api/chat` 报 `expected "json" or a valid JSON Schema object`），但**完整支持 JSON Schema
> 结构化输出**（已实测：基本对象 / `oneOf` / 数组 + `oneOf` 均被接受且正确收敛到分支与
> required 字段）。故本步骤以 `scripts/gbnf_grammar.py` 产出 **JSON Schema dict**（顶层
> `{type:array, items:{oneOf:[5 工具]}}`，`name` 用 `const` 锁定，`arguments` 复用
> tools_v1 参数 Schema 且全部对象 `additionalProperties:false`），经 Ollama 原生
> `/api/chat` 的 `format` 字段实现约束。接入冒烟（qwen2.5:7b，前 3 用例）验证：**3/3 输出
> 合法 JSON 数组、工具名全对、`ToolCallsMissing`（R-V1-3）根除**；2 例判分失败为
> 「可选参数缺省/枚举精确匹配」的内容质量问题，留待全量重测后再判（涉判分口径）。

> **判分口径第二轮修订（2026-09-28，已入 `judge_tools.py`，`--selftest` 通过）**：
> ① `query` 改**语义匹配**；② `diagnosis_summary` 只要求**非空**；③ `evidence_refs` 只比对 **type**（数组超集 / 集合覆盖）；
> ④ **应拒绝且正确拒绝不计退化**。旧 0.10/0.150/0.200 等值被新口径取代。

> **载体转向实证 → 全量补测（EXP-V1-003，2026-09-28）**：约束解码全量 2 模型 × 20 用例 × 3 次已跑完
> （原始落盘 `experiments/v1/raw/EXP-V1-003.jsonl` 220 条 + `.meta.json`，tag=`constrained-decoding`。
> 先后两次因 Ollama 环境问题失败，修复 `OLLAMA_MODELS=D:\.ollama` 与 `run_v1` 相对路径 meta bug 后成功）。
> **实测结论**：qwen 首次 **0.35** / 重试后 **0.95** / 可解析率 **1.00**；deepseek 首次 **0.45** / 重试后 **0.90** / 可解析率 **1.00**。
> **格式退化（JSON 不可解析 / 参数缺失 / `ToolCallsMissing`）已根除**，工具调用链路稳定性达成；
> 但**首次成功率未达 Pass（≥90%）**，叠加云端上界（EXP-V1-002）0.60<0.90 → 按四象限**用例/Schema 需复审**，
> 处置①未单独翻转首次成功率到 Pass（详见 `reports/p0-report-v1-tool-call.md` §十）。

### 4.2 ② few-shot 示例增强

| 项 | 内容 |

### 4.3 ③ Schema 简化

| 项 | 内容 |
|---|---|
| 手段 | 在**不改变语义**的前提下精简 Schema：① 减少嵌套层级；② 减少可选字段数量；③ 枚举值收敛；④ 长描述缩短为要点 |
| 硬约束 | **不得**删减 `query_sensor` / `search_knowledge` / `query_graph` / `get_maintenance_history` / `generate_report` 五个工具的必需参数；Schema 若变更 → **升版为 `tools_v2.json`**（见 `docs/prj-ledger-version-lock.md` 变更即升版纪律） |
| 代价 | ① 信息量下降可能增加歧义；② 若升版，**已完成的 V1 结论需重跑**（成本高），故**优先做 ①②，最后才动 Schema** |
| 留痕要求 | 记录 Schema 版本、变更 diff、前后指标对比 |

### 4.4 ④ 仍不达标 → 转"本地推理 + 云端工具调用"混合形态

| 项 | 内容 |
|---|---|
| 触发 | 执行完 ①②③ 后，首次成功率**仍 < 90%** |
| 方案 | **本地模型负责 R-1（意图识别）与 R-4（答案归纳）**，把 **R-2（工具调用规划）与 R-3（参数抽取）交给云端模型** |
| 理由 | 工具调用是**结构化输出**任务，对输出纪律要求最高；本地 7B 模型最薄弱的正是这一点。而答案归纳可容忍少量措辞波动，且涉及**证据原文**（不宜外传），故留在本地 |
| 代价（**必须显式标注**） | ① 引入**云端调用成本**与预算熔断（`budget:cloud:{day}`，见 V5.0 §7.1）；② **数据出境风险**：工具调用参数含设备号与时间窗，须脱敏或走"仅传结构化参数、不传原文"策略；③ 端到端延迟增加（网络往返），需**单独统计**（`P95 端到端 < 3s` 仅适用本地命中路径口径）；④ 增加外部依赖 |
| 留痕要求 | 记录混合形态下的：端到端 P95、云端调用次数/成本、工具调用首次成功率（预期 >95%） |

> **2026-09-30 P7 实施与实测（方案 A，EXP-M02-001）**：本步骤④已**正式实施**——**R-2（工具规划）+ R-3（参数抽取）转云端**（`Qwen/Qwen3.8-27B` @ ModelScope，结构化输出 `response_format=json_schema`），多工具**不拆步**（采用方案 A 云端单响应编排，因 P6 已证否方案 B 本地拆步）。
> 实测 **首次成功率 0.60（12/20）→ 整体 No-Go**：单工具 67% / 多轮 33% / 无效拒绝 67% 均 <70%，参数校验 75%、多工具 50% 落中间；**多工具集合覆盖 1.00 但用例级仅 50%** → **编排无问题、卡参数值**（参数值正确率 **0.5882**，与 EXP-V1-005 云端口径同源）；**未达本表预期（>95%）**。
> 代价已显式留痕：云端调用 20 次（未超 `budget_lock=20`）；热 P95 **22529 ms**（端到端延迟必须单列，`P95<3s` 仅适用本地命中路径）；数据出境 = 合成用例、仅传脱敏结构化参数、不传证据原文。
> **结论：处置链 ①②③④ 已全部执行仍 No-Go → 指向优先复审参数值判据/用例口径（而非继续换/加模型）**。详见 `experiments/v1/EXP-M02-001.md`、`reports/p0-gate-review.md` §三 决策5。

### 4.5 处置动作决策树

```
首次成功率
  ├─ ≥ 90% 且 可解析率 ≥ 95%   → Pass：直接采用
  ├─ 70%–90%                  → 中间区间
  │     ↓ ① 约束解码（载体=JSON Schema） → 重跑
  │     ↓ 仍 <90%：② few-shot      → 重跑
  │     ↓ 仍 <90%：③ Schema 简化   → 重跑（须升版 Schema）
  │     ↓ 仍 <90%：④ 转混合形态     → 定稿
  └─ < 70%（两模型均是）        → No-Go：云端工具调用转正
```

### 4.6 ⑤ 架构切分：多工具编排（2026-09-28 定稿）

> **依据**：分层实测 `EXP-V1-003`「多工具」双模型 **0.00**（结构性硬限），`EXP-V1-005` 云端约束解码「多工具」亦仅 **50%（中间区间）**。多工具要求单响应内组织多个工具并各自抽全参数，**7B 无法承担、27B 也仅为中间档** → 从"整线云端转正"再细化出**多工具架构切分**。

| 项 | 内容 |
|---|---|
| 触发 | 用例「多工具」类型首次成功率 **< 70%**（本地基线 0.00） |

## 五、三个关键风险（**必须逐条设强制校验**）

### 5.1 风险一：`think` 污染

| 项 | 内容 |
|---|---|
| 现象 | `deepseek-r1:7b` 输出中夹带 `think` 推理块；若**直接拿去判 JSON，会把格式失败误判为能力不足** |
| 影响 | 低估模型能力 → 错误结论 → 错误分工 |
| **强制校验** | **必须先剥离 `think`，再判 JSON**；剥离失败或剥离后为空 → 记为"think 污染失败"，**单独统计 `think` token / 总输出 token** |
| 校验手段 | 适配层（`scripts/llm_adapter.py`）统一剥离，**两个模型走同一入口**；剥离逻辑须有单测 |
| 留痕 | 报告中单列"think 污染率"与"输出冗长度"（8 项指标之第 8 项） |

### 5.2 风险二：量化公平性

| 项 | 内容 |
|---|---|
| 现象 | 两个模型若量化档不同（如 Q4_K_M vs Q8_0），对比**不公平** —— 低量化模型输在数值精度而非能力 |
| 影响 | 分工决策建立在不可比的数字上 |
| **强制校验** | ① 记录**两个模型的实际量化档**（`ollama show <model> --modelfile`）；② 对比时**必须同档**；③ **胜出者须补 Q8（或 FP16）复核**，确认结论在更高精度下不倒转 |
| 校验手段 | 实验中登记 `image_model_digests` + 量化档；复核实验新开 `experiment_id` |
| 兜底 | 若无法拉齐量化档，报告中**必须显式声明**该对比不公平，并降级为"仅作参考" |

### 5.3 风险三：Ollama 静默退化

| 项 | 内容 |
|---|---|
| 现象 | Ollama 在某些请求下返回 **200 但无 `tool_calls`**（或退化为纯文本），**不报错** |
| 影响 | 缺失数据被当成"失败"计入，甚至造成指标失真 |
| **强制校验** | **必须断言响应中存在 `tool_calls`**；不存在则：① 标记该次为"静默退化"；② 重试计数 +1；③ 单独统计退化次数并在 `anomalies` 字段记录 |
| 校验手段 | `scripts/llm_adapter.py` 解析后置位 `AdapterResult.tool_calls_missing`（**默认不抛异常**，避免单条失败中断整批）；判分器（`scripts/judge_tools.py`）据该标志记 **`格式退化`** 并单独计数；原始响应完整落盘以便事后复核 |
| 补充 | 记录 Ollama 版本为 **0.34.2**（API `http://127.0.0.1:11434`）；**存在 0.34.3 可升级，已裁决锁定 0.34.2 不升级** → 版本漂移风险见 `docs/prj-ledger-risk-register.md`（**R-新3**） |

> **风险等级调整说明**：因"是否升级到 0.34.3"会改变复现条件，**V1 全流程须固定在同一 Ollama 版本**；若中途升级，**必须全部重跑**并在报告中升版环境基线。

## 七、云端 baseline 的作用说明（上界校准）

| 项 | 说明 |
|---|---|
| **定位** | **仅作上界校准（upper bound calibration）**，**不是**默认部署方案 |
| **执行方式** | `python scripts/run_v1.py --models <cloud-model> --repeat 1 --tag baseline_cloud`（每条用例跑 1 次，20 条） |
| **要回答的问题** | ① 这批用例**本身的难度是否合理**（若云端也做不到 90%，说明用例设计或 Schema 有问题，而非模型问题）；② 本地模型与上界的**差距有多大**、差距体现在哪几项指标上；③ 若走混合形态，云端侧能达到的水平是多少 |
| **不做的比较** | ❌ 不把云端结果与本地结果做成"谁更好"的排名；❌ 不用云端结果作为 Pass/No-Go 判据（判据只针对本地模型） |
| **成本纪律** | 云端调用受 `budget:cloud:{day}` 预算熔断约束（V5.0 §7.1）；20 条 × 1 次为**一次性上界校准**，不做重复实验 |
| **数据纪律** | 上界校准**仅发送脱敏摘要与结构化参数**，**不发送**证据原文（V5.0 §七 防线①） |
| **结论写法** | 报告中写作："云端 baseline（上界）：首次成功率 _%（_/20）—— 用于校准用例难度与衡量本地差距，不作为部署依据" |

### 7.1 差距判读规则

| 情形 | 判读 | 动作 |
|---|---|---|
| 云端 ≥90%，本地 Pass | 用例难度合理，本地可用 | 正常采用本地 |
| 云端 ≥90%，本地中间/No-Go | **能力差距在模型，不在用例** | 按 §四 加固；必要时转混合形态 |
| 云端 **<90%** | **用例设计或 Schema 可能有问题** | **先修用例/Schema 再重测**，不得直接下"本地模型不行"的结论 |
| 云端与本地均 ≈100% | 用例过易，**判别力不足** | 补充难度分层用例（多工具/参数校验/无效拒绝），重测 |
