## 〇、一句话

把 V1 判据的被测对象从「`run_e2e` 单轮 harness + prompt v4」换成「**产品 Agent 本体**
（`app/agent/` 工具面 + `agent_diagnose` 循环 + 产品提示词）」，让「是否可切默认」的裁决
第一次建立在产品自身行为上，而不是建立在产品的替身行为上。

## 一、为什么要立项 D（路径 C 的边界）

`EXP-P7-GATE3`（路径 C）已把被测**工具面**对齐产品（只读 4 工具），并拿到一版可信分数：
首成 89.33%，多轮 100%，单工具/多工具为中间区间。但它**在结构上**仍然只测：

| C 测到 | C 测不到 |
|---|---|
| 单轮内「该调哪个工具、参数填什么」 | 多轮自主循环（何时再调一个工具、何时收口） |
| 提示词 = `prompts/tool_call_prompt_v4.md`（冻结区） | 提示词 = `app/agent/prompt.py`（产品自己的系统提示词） |
| 无状态单次请求 | 证据归集 `_Collector` / 置信度公式 / finalize 引用校验 |
| 无预算/步数护栏 | `max_steps` 封顶、`BudgetGuard` 熔断、失败重试降级路由 |
| 无降级与兜底路径 | degrade / escalate 空转 / 降级出报告 |

换言之：**C 证明的是「模型在产品工具面上会选工具」，D 要证明的是「产品 Agent 能端到端交付」**。
后者的实证目前只有 `scripts/smoke_agent_cloud.py` 的 3 次手工实跑（156 s / 226 s，RPT 落 PG），
没有分档判据、没有可复现的用例矩阵 —— 这正是 U2（P95 口径）与「切默认」裁决缺的那块拼图。

## 二、目标 / 非目标

**目标**
1. 用同一套 V1 用例集（主集 20 + 迁移集 5）驱动**产品 Agent 本体**，得到分档判据表；
2. 覆盖多轮循环、证据归集、收口质量、护栏（步数/预算/重试）四类 C 未覆盖的行为；
3. 复用既有档线（**不放宽**），复用 `aggregate_runs` 的聚合口径（同日多轮）；
4. 产出可复现 harness（脚本入库 + 自检），而非一次性实跑。

**非目标**
- 不改档线、不改用例集考点（除非按修订流程另行授权）；
- 不做性能基准（延迟由 U2 的异步诊断口径承接）；
- 不替换 `run_e2e`（它仍是「模型能力上界」的快速探针，两者互补）。

## 三、被测对象与 harness 设计

```
V1 用例 ──▶ 产品 Agent 本体（agent_diagnose 循环 + tool_registry + app/agent/prompt.py）
              │  工具执行层 = 打桩（返回中性 mock 结果，与 run_v1 STEP_CHAIN 同款口径）
              ▼
        逐用例落盘 raw（steps / tool_calls / content / agent_steps / report_id）
              ▼
        judge_record（复用 judge_tools，判分语义零改动） + aggregate_runs 聚合
```

| 设计点 | 规定 |
|---|---|
| 入口 | `scripts/run_agent_gate.py`（新建），形态 = `AUSCULT_DIAGNOSIS_MODE=agent` + `AUSCULT_LLM_BACKEND=cloud`，工具层打桩 |
| 提示词 | **产品提示词 `app/agent/prompt.py`**（不再用 prompt v4）—— 这是 D 与 C 的本质差异 |
| 工具面 | 产品 4 只读工具（`tool_registry` 只读子集，写操作护栏保留并单独报告） |
| 用例驱动 | 每条用例按 `context` 重建消息序列，驱动 Agent 循环至收口（`max_steps` 默认 4） |
| 判定口径 | ① 工具选择/参数：**复用 `judge_tools`**；② 循环质量：新增 `agent_steps` 派生指标（步数、是否空转、是否越权调用）；③ 收口质量：诊断 JSON 可解析 + 证据引用通过 finalize 校验 |
| 分档映射 | 单工具/参数校验/多工具/多轮 沿用；新增「护栏」维度（越权调用=0、无空转）单列报告，**不计入 V1 六档**（避免改档线） |
| 轮数 | 3 轮同日、repeat=1、聚合口径同 H22；不挑选 |
| 落盘 | `experiments/v1/raw/EXP-P7-GATE-D-R{1,2,3}.jsonl` + `.agg.json`（只增不改） |

## 四、成本估算

| 项 | 估算 |
|---|---|
| 云端调用 | 主集 allow 17 × 3 轮 = **51 次**（迁移集被规则门短路，云端 0）；Agent 多轮可能放大到 ≈ 17 × 2 轮 × 3 = 102 次量级 → **按 102 次预留** |

## 五、风险与对冲

| # | 风险 | 对冲 |
|---|---|---|
| 1 | 打桩工具结果与真实工具分布不同 → 模型的第二轮选择失真 | mock 结果与 `run_v1.STEP_CHAIN` 逐字同源（中性、不泄漏期望值）；报告中显式声明「打桩口径」 |
| 2 | Agent 循环把 1 条用例变成多次云端调用 → 预算超预期 | 开跑前按 §四 预留 102 次；`max_steps` 封顶；跑前先 `--selftest` 零网络验证 |
| 3 | 「护栏」维度被顺势变成新档线（隐性放宽/加严） | 明确护栏**只单列报告、不进六档**；任何档线变更走 2026-09-28 先例的授权流程 |
| 4 | D 的分数与 C 不可比 → 对外口径混乱 | 对外一律标注「被测对象 + 工具面 + 提示词版本」三元组；禁止跨口径直接比大小 |
| 5 | 判分器为 Agent 形态打补丁 → 判分语义漂移 | 工具选择/参数判定**复用** `judge_tools`，新增指标只做派生字段，不改既有成功判定 |

### 七之二、实测回填（2026-10-20，`EXP-P7-GATE-D`）

**已开工并跑完首版**：`scripts/run_agent_gate.py` + `tests/test_agent_gate.py`（6 例锁）；
首成 **62/75 = 82.67%**，四档工具类中间区间、拒止/澄清 Pass、**无一档 No-Go**；13 个失败全部为参数值错。

首版暴露的三件事（决定了「D 还不足以裁决切默认」）：

| # | 事实 | 对设计的影响 |
|---|---|---|
| 1 | **打桩漏装**（`main()` 未调 `install_stubs()`）→ 首跑走真实工具，`query_sensor` 因无告警 4 次报错 | 已修 + 回归锁；**下一版必须在 §三 设计里把「装桩」写成可断言的前置**，而不是默认约定 |
| 2 | **收口契约错配**：`v1-014` 三轮以 markdown 表格「回答」而非诊断 JSON 收口（`json_parse_ok=False` 3/3） | §三 判定口径需增加 `answer_mode` 单列指标（问答型用例允许自然语言收口，不进六档） |
| 3 | **循环不自行收口**：`max_steps=2` 下 94% 样本被强制收口 | `max_steps=4` 的完整循环是 D 的**必需**配置（预算需单排日），非可选项 |

结论：**D 的下一版 = 修 harness（告警前置 + 收口放行 + max_steps=4）→ 重跑 → 才可作切默认凭据**。
详见 `experiments/v1/EXP-P7-GATE-D.md` §3.4/§3.5/§四。

**v2 修复状态（2026-10-20 同日，离线完成、零云端）**：① 告警前置 → `infer_alarm()` 注入最小 `AlarmEvent`
（19/25 用例注入；被驱动用例 16/17 有告警）；② 收口形态 → `answer_mode` 单列（不进六档）；
③ 步数 → 回到产品默认 4。**云端复跑尚未执行**（当日预算已封盘 345/340，且需先修预算计数器漏计 `31%`）。
复跑条件与命令见该实验 §5.1。
