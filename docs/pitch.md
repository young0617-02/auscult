## 一、90 秒电梯解说（开场）

「这是一个跑在本地、以告警为入口、会自己查资料并给出**带出处**维修建议的工业设备诊断 Agent。数据不出厂，结论可追溯。系统把『告警→证据汇聚→诊断推理→报告生成→高风险人工审核』串成一条可审计的闭环；本机双模型（qwen2.5:7b 工具调用 + deepseek-r1:7b 诊断推理）跑推理，云端仅作脱敏兜底，置信度不足时降级、高风险时强制人工确认。本次演示用一条真实离心泵轴承振动告警，走完整条链路。」

## 四、Q&A 预演（含尖锐问题）

### 高频问题

| 问题 | 建议回答 |
|---|---|
| Q1 数据会不会上传到公网？ | 不会。本地推理为主；仅置信度∈[0.50,0.75) 时升级云端，且**只传脱敏摘要与结构化参数、不传证据原文**，device_id 哈希化（设备#sha256[:6]），按天 340 次预算熔断 |
| Q2 诊断结论能不能信？ | 证据来自经过检的语料，每句结论带 citations 出处可反查；高风险不强制审核不自动定稿；Phase 5 引用正确率 0.9861、幻觉率 0.0%（模拟数据，正式评测待扩语料） |
| Q3 出故障谁负责？ | 高风险走人工审核 + 职责分离（提交人不得自审）+ 报告幂等（同告警不重复出），审计 append-only |
| Q4 与通用 LLM 直接问有何区别？ | 有编排层保证：五档条件路由（降级/升级/审核/定稿）、跨存储一致性 Outbox 对账、图谱有限支撑、结构化报告而非自由发挥 |

### 尖锐问题（必答）

| 问题 | 诚实口径（不编造） |
|---|---|
| A1 为什么 Neo4j 图谱是空的？ | `extract_triples` 抽帧导入依赖 P1 冻结 LLM 产物与 schema 关系词表，D6–D7 定为「非基建引导判据」、由演示数据预置（D8–D9）承载。当前图谱数据未预置，诊断主要靠文档混合检索 + 传感器；如需图谱演示，需补预置数据（已登记 `ISS-042` 同类工程侧口径，`demo/scenario.md` §四 备注） |
| A2 端到端为什么这么慢？ | P95 端到端（含本地生成）9.2s，Phase 5 已记录；根因是本地 7B 生成输出较长。优化路径已列（流式输出 / max_tokens 收紧 / 高频缓存），属 Phase 6 后路线，演示前建议预热 |
| A3 告警状态为什么只有 open？ | `alerts.status` 当前唯一写入 open（告警引擎固定），acked/closed 无流转代码 —— 已登记 `ISS-039`（Q6 登记不修）。演示口径统一为"只读 + 单状态筛选"，**不声称告警可确认/关闭** |
| A4 会话追问持久吗？ | `qa_log` 仅存进程内、重启即失，无落库 —— 已登记 `ISS-041`。演示口径为"单次会话内追问"，不声称跨重启保持 |
| A5 超时是不是返回 504？ | `E_TIMEOUT` 映射已登记 (504) 但代码无主动抛出点，实际超时走其它错误码 —— 已登记 `ISS-038`。演示与文档不声称"超时返回 504" |

## 五、失败兜底预案

| 现场失败 | 兜底 |
|---|---|
| 后端未起 | 按 `demo/scenario.md` §一 步骤 4 启动 uvicorn :8000 |
| 诊断太慢/卡 analyze_sensor | 是本地 LLM 生成慢（P95 9.2s 已知）；等待 30–60s，或换小问题/预热；不慌、如实说明瓶颈 |
| 审核/降级路径不稳 | S3/S4 依赖模型置信度随机性，演示前预跑一次确认路径（`scenario.md` §备用已注） |
| 图谱无数据 | 按 A1 口径如实说，不改演示主流程（主流程是文档检索闭环） |
| 一切失败 | **演示纪律：复现既有能力，不是演示新功能**；失败时停、复位、不编造（`scenario.md` §六） |
