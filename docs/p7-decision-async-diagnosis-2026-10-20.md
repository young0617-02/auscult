# U2 判决记录：诊断产品形态改为「异步诊断 + 实时进度」

> **状态**：✅ **已判决（2026-10-20）** ｜ **判决人**：所有者（原话：「U2 产品形态口径（异步诊断」）
> **对应未决项**：`docs/p7-design-agent-diagnosis-2026-10-19.md` §六 U2
> **影响面**：产品形态口径 / 前端进度呈现 / 性能指标口径；**不涉及**判据档线、默认形态、代码行为

---

## 〇、一句话

Agent 化诊断的**产品形态**定为「**异步诊断 + 实时进度推送**」：用户发起诊断后立即得到
「受理中 + 实时进度」，结论经审核流后推送/可查 —— **不再承诺同步秒级返回**。

## 一、判决依据（已实测事实，不新增结论）

| 事实 | 数值 | 出处 |
|---|---|---|
| 云端 Agent 单轮工具调用延迟 | 5.5–37 s（并行多工具轮更慢） | `docs/p7-design-agent-diagnosis-2026-10-19.md` §7.0 |
| 云端 Agent 端到端 | **156 s**（图级）/ **226 s**（API 级，含一次 >90 s 超时重试） | 同上 |
| 既有 P95 口径 | < 3 s（确定性形态基线 9.25 s 已未达标） | 同上 |
| 检索预热 | ≈ 30 s | 同上 |
| 实时进度通道 | Socket.IO 已有进度事件（前端已渲染 Agent 工具调用列表） | `client/components/features/DiagnosisConsole.tsx` |

**结论**：Agent 化与「同步 + P95<3s」在云端形态下**不可兼得**（实测差距 1.5–2 个数量级）；
硬扛该口径只会得到「指标永远不达标」的虚假结论。故按产品实际交互重定形态，而非改指标数值迁就实现。

## 二、形态定义（本判决固定下来的口径）

| 项 | 规定 |
|---|---|
| 交互 | 发起诊断 → 立即返回「已受理 + 任务标识」→ 期间经 Socket.IO 推送**实时进度**（Agent 步骤、当前工具、重试/降级事件）→ 完成后进入既有 `waiting_review` 审核流 |
| 审核流 | **不变**（`rev_dev` 审核 → `report_id` 落 PG；4h 通知 / 24h 超时降级） |
| 性能口径 | 取消「同步 P95<3s」作为 Agent 形态的验收线；改为**异步口径**：受理响应 P95、进度事件到达延迟、端到端完成时间分位数（按 U2 实测分布另立基线） |
| 降级路径 | 不变（LLM 失败 → 重试 → 降级出报告；降级事件须推送，不得静默） |
| 超时角色化 | 不变（diagnose 30 s / **agent 90 s**，env 可调） |

## 三、明确不做（防止范围漂移）

1. **不改判据档线**、不改 V1 用例集、不改 `run_e2e` 口径（那是路径 C/D 的事）；
2. **不因此把 Agent 设为默认**（默认仍 `deterministic`，切默认仍须过闸门）；
3. **不改前端交互框架**（仅进度呈现口径；无新页面/新流程）。
