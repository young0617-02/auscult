# ADR-001：本地双模型分工（`qwen2.5:7b` 工具调用 + `deepseek-r1:7b` 推理）

> **层级**：项目级长期有效（ADR）｜ **对应里程碑**：`M6.1`（Phase 6 文档收口 · D5 产出）｜ **状态**：🟢 **活动**｜ **最近更新**：2026-10-10

## 二、背景（Context）

- 本地显存 8GB（RTX 4060 Laptop），两个 7B 模型**不可同时常驻**，须按角色分工与按需调度（`plan/工业设备诊断 Agent.md` §2.2、§3.9）。
- 候选双模型能力互补：`qwen2.5:7b` 原生支持 Function Calling；`deepseek-r1:7b`（蒸馏版）**不支持结构化工具调用**但长链推理强（`plan/工业设备诊断 Agent.md` §3.4、§3.7）。
- 若不做角色切分，单模型既做工具调用又做诊断推理，会在结构化输出与推理质量两头同时受限。

## 三、决策（Decision）

**本地双模型按角色分工**：

| 角色 | 模型 | 一句话理由 |
|---|---|---|
| 工具调用 / 结构化决策 | `qwen2.5:7b` | 原生 FC、JSON 可解析率高、无 `think` 污染 |
| 诊断推理 / 根因分析 | `deepseek-r1:7b` | 长链推理强，仅做文本推理、不产生工具调用 |
| 云端模型 | 仅兜底与上界校准 | 低置信度升级路径，不作默认部署 |

**决策摘要 + 指针**（完整判据、处置链、实测数字一律见上游文件，此处不重复）：

| 内容 | 指针 |
|---|---|
| 角色×模型矩阵、判据（Pass/中间/No-Go）、中间区间处置链 ①约束解码→②few-shot→③Schema 简化→④转混合形态 | `docs/p0-decision-model-role.md` §二、§三、§四 |
| 模型→角色映射结论表与 8 项指标实测总表（2026-09-28 回填） | `docs/p0-decision-model-role.md` §六 |
| 双模型 digest 与版本锁定 | `docs/prj-ledger-version-lock.md` §二.2 |
| 三个强制校验风险（`think` 污染 / 量化公平性 / Ollama 静默退化） | `docs/p0-decision-model-role.md` §五 |

## 四、V1 云端转正后的现状偏差（如实登记）

上游 P0 决策的"本地双模型分工"在 V1 实测后发生**分工位移（非全上云）**：

| 口径 | 内容 | 出处 |
|---|---|---|
| 分工位移 | **R-2（工具调用规划）/ R-3（参数抽取）转云端**（云端 R-2/R-3 臂：prompt v1 + `tools_v4` + `tools` 通道）；**R-1 意图识别、R-4 证据归纳/诊断推理、R-5 审核摘要、检索层、写操作/审计、有效拒绝、降级兜底保持本地** | `docs/p0-decision-model-role.md` §4.6、§6.1 |
| 评测权威入口 | M0.2 权威入口 = 端到端（本地规则门 → 云端工具调用），`scripts/run_e2e.py` | `README.md` §当前状态速览 |
| 产品诊断链路 | `app/` 运行态：本地 Ollama 双模型承担诊断推理，置信度 ∈ [0.50, 0.75) 时云端兜底（脱敏 + 预算熔断） | `app/router/cloud.py`、`README.md` §当前状态速览 |
| 说明 | `README.md` 与架构文档分层图中"本地：`qwen2.5:7b`（工具调用）"为**本地双模型分工的展示口径**；评测/工具链路的**执行口径**已按 §4.6 分工位移走云端臂，两处差异由本节如实登记 | 本 ADR（综合以上出处） |

## 五、备选方案与放弃理由（Options & Rejected）

| 备选 | 放弃理由 | 出处 |
|---|---|---|
| 单模型承担全部角色（`deepseek-r1:7b` 兼做工具调用） | 蒸馏版不支持结构化工具调用，且 `think` 长链会污染 JSON（须先剥离再判） | `plan/工业设备诊断 Agent.md` §3.4；`docs/p0-decision-model-role.md` §5.1 风险一 |
| `qwen2.5:14b` 替代 7B | Q4 量化 ≈9GB，装不进 8GB 显存（硬件不允许） | `plan/工业设备诊断 Agent.md` §3.7 候选评分矩阵 |
| `qwen2.5:3b` 为主力 | 能力不足，仅作意图分类/查询改写备选，未采纳为主力模型 | `plan/工业设备诊断 Agent.md` §3.7 |

## 六、后果（Consequences）

| 类型 | 内容 |
|---|---|
| ✅ 正面 | 显存 8GB 约束下可用性最大化；角色可判据化（8 项指标分开报、按类型分档），分工决策有实测支撑 |
| ⚠️ 负面 | 7B 本地首次成功率不足 → 处置链 ①②③④ 全部执行仍 No-Go，R-2/R-3 最终转云（分工位移已如实登记于 §四） |
| 📎 已知边界 | 量化档 Q4_K_M 对比的 Q8/FP16 复核留待后续迭代（`docs/p0-decision-model-role.md` §6.3）；R-4 本地可用性已由 `EXP-R4-001` 实测 Pass 并闭环 `ISS-014`（同上 §6.1） |
