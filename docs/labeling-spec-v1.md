> **版本**：v1 ｜ **定稿日期**：D1–D2 ｜ **状态**：已定稿（规范可执行；一致性检验待 P5）
> **主场景**：离心泵轴承振动异常诊断

## 一、标注目标

本评测集是 **V2 检索质量对比** 与 **P2（检索质量达标）/ P5（一致性检验）** 的**唯一基准**。目标：

1. 给 V2 提供一把**统一尺子**：Milvus 与 pgvector 两条路线用同一批问题、同一批标准答案、同一批相关块，算出的 `Recall@5`/`MRR` 才具可比性；
2. 给 P1 建库提供**标注锚点**：明确"哪些块是应该被检索出来的"，反向检验切块粒度是否合理；
3. 给置信度校准提供**正确/错误标签**（V5.0 §6.1 的温度缩放与 ECE 计算依赖此标注）。

## 二、字段定义（`golden_set_v1.jsonl`，每行一个 JSON 对象）

| 字段 | 类型 | 必填 | 定义 | 约束 |
|---|---|---|---|---|
| `qid` | string | ✅ | 唯一题号 | 格式 `Q001`–`Q050`，**连续不跳号** |
| `question` | string | ✅ | 提问原文（用户口吻） | 8–60 字；不得含答案 |

## 四、7 个类别的判定标准与边界例子

### 4.1 类别判定表

| 类别 | 判定标准（满足即归此类） | 边界例子 |
|---|---|---|
| **设备手册** | 问的是**产品本身**的结构、参数、铭牌、原理、部件名称 | ✅"离心泵的机械密封在哪个位置" → 手册<br>❌"离心泵振动大怎么处理" → 故障诊断（问处置，不是问结构） |
| **故障诊断** | 问的是**现象 → 原因**的推断或排查路径 | ✅"振动频谱出现 4 倍频说明什么" → 故障诊断<br>❌"振动频谱怎么测" → 传感器与测量（问方法） |
| **维护规程** | 问的是**周期性/计划性**的保养、点检、更换周期、作业步骤 | ✅"轴承润滑脂多久更换一次" → 维护规程<br>❌"轴承已损坏怎么换" → 故障诊断 + 维护规程，**取主类=故障诊断**（触发因是故障） |
| **传感器与测量** | 问的是**测量方法、仪器、量程、安装、精度、单位换算** | ✅"加速度传感器磁吸和螺柱安装差别" → 传感器与测量<br>❌"振动标准规定多少 mm/s" → 振动标准（问判据值） |
| **振动标准** | 问的是**标准条款、判据阈值、等级分区、引用编号** | ✅"ISO 10816 振动烈度分区怎么划" → 振动标准<br>❌"我们的泵算不算超标" → 故障诊断（需结合具体数据判断） |
| **历史工单** | 问的是**我方/客户历史记录**中的具体事件、处理、耗时、更换件 | ✅"3 号泵去年换过几次轴承" → 历史工单<br>❌"轴承一般寿命多久" → 维护规程（问通例，不问历史） |
| **安全规范** | 问的是**人身/设备安全、停机条件、作业许可、隔离挂牌** | ✅"什么情况必须紧急停机" → 安全规范<br>❌"高温报警阈值设多少" → 振动标准或设备手册 |

### 4.2 跨类处理规则

1. **单值原则**：`category` 只能填一个。跨类时取**提问的意图主类**（即"用户想知道的是什么"），而非"答案涉及什么"。
2. **优先顺序**（当前两类冲突时，按此降序取主类）：
   `安全规范 > 故障诊断 > 振动标准 > 传感器与测量 > 维护规程 > 设备手册 > 历史工单`
3. **必须备注**：任何跨类判定，`notes` 中必须写明"同时涉及 X 类，取主类为 Y"。

## 五、`answer_points` 拆分粒度规则与难度分级

### 5.1 `answer_points` 拆分规则

| 规则 | 说明 |
|---|---|
| **R1 独立性** | 每条要点必须**可单独判定对错**，不得写成连贯段落 |
| **R2 最小充分** | 拆到"再拆就失去意义"为止；一般 2–4 条，上限 5 条 |
| **R3 不含过程** | 不写"先查 A 再查 B"这类**顺序**表述（顺序属于检索命中后的组织，不是要点） |
| **R4 数值必须精确** | 涉及阈值/周期/频率时，要点里必须带数值与单位 |
| **R5 不写"正确/错误"字样** | 要点是**内容**，判定由评分者做 |
| **R6 不引入语料外知识** | 要点必须是模拟语料中**能找到依据**的内容 |

**示例（Q007）**：

```json
{
  "qid": "Q007",
  "question": "离心泵轴承外圈剥落时，振动频谱上会出现什么特征？",
  "answer_points": [
    "出现外圈故障特征频率 BPFO 及其谐波",
    "BPFO 两侧常伴有转频边带",
    "时域上出现周期性冲击，包络谱中 BPFO 更明显"
  ],
  "relevant_chunk_ids": ["manual_pump_A_ch04_b012", "case_bearing_outer_003_b02"],
  "category": "故障诊断",
  "difficulty": "中",
  "source_doc": "离心泵产品手册（模拟）- 第 4 章 故障排查",
  "notes": "涉及传感器与测量（包络谱方法），取主类=故障诊断"
}
```

**反例（不要这样写）**：
- ❌ `"先看频谱再看包络谱，然后对比标准判断"` —— 违反 R3（含顺序）与 R1（不可独立判定）
- ❌ `"轴承坏了"` —— 违反 R4（无数值/特征）与 R2（信息量不足）

### 5.2 难度分级标准

| 难度 | 判定标准（满足任一即归该级） | 示例 |
|---|---|---|
| **易** | ① 问题关键词与语料标题/正文**字面高度重合**；② 命中 1 个块即可完整作答；③ 无同义词替换 | "离心泵机械密封的作用是什么" |
| **中** | ① 正确块需跨 **2–3 个块**综合；② 存在**同义/近义**替换（如"异音"↔"异常噪声"）；③ 需要一步概念转换（频率→部件） | "振动频谱出现 4 倍频说明什么" |
| **难** | ① 需理解**上下位/因果**关系；② 答案分散在表格/图注文本中；③ 存在**强干扰块**（术语相似但结论不同）；④ 需多跳（≥2 步） | "同样的振动幅值下为什么高速泵和低速泵判定不同" |

> **判定纪律**：难度以"**正确块被检索出来的难度**"为准，**不以"回答难度"为准**。

## 六、`relevant_chunk_ids` 相关性判定标准

### 6.1 相关性等级定义

| 等级 | 名称 | 定义 | 是否计入 `relevant_chunk_ids` |
|---|---|---|---|
| **L3** | 充分相关 | 该块**单独**包含 ≥1 条 `answer_points` 的完整依据 | ✅ **计入** |
| **L2** | 部分相关 | 该块包含要点依据的**一部分**（需与别的块合并才完整） | ✅ **计入**（但 `notes` 必须标注"部分相关"） |
| **L1** | 弱相关 | 同主题、术语重合，但**不含**任何要点的依据 | ❌ 不计入 |
| **L0** | 无关/干扰 | 主题不同，或结论相反 | ❌ 不计入（**应作为负例观察**） |

### 6.2 "部分相关是否算"的处理（**明确规则**）

> **规则**：`Recall@5` 关心的是"**该找到的有没有找到**"，而不是"找得多精"。因此 **L2 部分相关必须计入** `relevant_chunk_ids`。
> **但必须留痕**：凡计入 L2 的条目，`notes` 中必须写 `部分相关：<chunk_id>`，便于后续分析"部分相关占比"是否影响两条路线的对比公平性。

### 6.3 相关性标注的正反例对比

| 场景 | 判断 | 理由 |
|---|---|---|
| ✅ 块标题即"轴承外圈故障特征频率"，正文给出 BPFO 公式 | **L3 计入** | 单独包含要点 1 |
| ✅ 块正文只给了 BPFO 公式，边带说明在另一块 | **L2 计入**（+ notes） | 包含要点 1 的一部分，要点 2 需别的块 |
| ❌ 块是"离心泵概述"，提到轴承但对故障频率只字未提 | **L1 不计入** | 同主题但无依据 |
| ❌ 块是"滚动轴承 vs 滑动轴承选型"，术语高度相似 | **L0 不计入**（干扰块） | 无要点依据；应在 `notes` 里标"干扰块" |
| ❌ 块里写"BPFO 与轴承故障无关" | **L0 不计入** | 结论相反 |

### 6.4 数量约束

| 约束 | 值 | 理由 |
|---|---|---|
| 每题的 `relevant_chunk_ids` 下限 | 1 | 无相关块的题不可用于 `Recall@5` |
| 上限 | 6 | 超过则说明切块过碎或题目过宽，**须回到切块粒度排查** |
| 全集平均 | 目标 2–3 个/题 | 过低则 `Recall@5` 判别力弱；过高则指标虚高 |

## 七、单人标注的可信度局限声明（**必须随本规范与评测集出现**）

> **局限声明**：
> `golden_set_v1` 由**单人标注**，未做双人独立标注与一致性检验，因此 `answer_points` 与 `relevant_chunk_ids` 存在**主观偏差风险**（尤其 L1/L2 边界与"难度"分级）。本评测集当前定位为**P0 阶段可用基准**，用于**两条路线之间的相对比较**，不宣称绝对质量水平。其绝对可靠性须在 **P5 双人标注 + Cohen's Kappa ≥ 0.7** 检验后重新确认。同时，全部语料为**模拟数据**，指标结论仅代表"**基于模拟数据的初步验证**"。

## 八、P5 双人标注 Cohen's Kappa 一致性检验计划

### 8.1 抽样方案

| 项 | 设计 |
|---|---|
| **标注对象** | `relevant_chunk_ids` 的相关性判定（L3/L2/L1/L0 四级）为**主检验项**；`category` 与 `difficulty` 为**次检验项** |
| **抽样比例** | **≥30%**，即 50 条中抽 **15 条**；若 Kappa 低于目标，扩大至 100%（50 条）重检 |
| **抽样方式** | 分层抽样：7 个类别每类至少抽 1 条；难度按易/中/难 = 6/6/3 抽取 |
| **标注人** | 标注人 A（原标注者）+ 标注人 B（**独立**，沿用 V5.0 §7.2 角色划分，由工程师或知识库管理员担任；禁止由 A 自己复核） |
| **盲标要求** | 标注人 B **不得看到** A 的标注结果；两人各自独立完成后才比对 |
| **候选池** | 每题给 8–10 个候选块（含正确块 + 干扰块，干扰块由 A、B 之外的第三方从同类别随机抽取），避免"候选里只有正确块"导致 Kappa 虚高 |

### 8.2 Kappa 目标值与判定

| 项 | 目标 | 判定 |
|---|---|---|
| **Cohen's Kappa（相关性四级）** | **≥ 0.70** | ≥0.70 = 可接受（substantial）；0.60–0.70 = 需修订规范后重检；<0.60 = 规范不可用，须重写判定标准 |
| 类别（`category`） | ≥ 0.80 | 类别判定应比相关性更客观，目标更高 |
| 难度（`difficulty`） | ≥ 0.60 | 难度分级主观性较强，目标适当放宽 |

**计算方式**：`κ = (Po − Pe) / (1 − Pe)`，其中 `Po` 为观察一致率，`Pe` 为随机一致率。同时报告 **观察一致率 Po** 与 **Kappa 的 95% 置信区间**（bootstrap 1000 次）。

### 8.3 分歧仲裁流程

```
① A、B 独立标注完成
        ↓
② 计算 Po / Kappa（脚本：scripts/kappa.py，P5 编写）
        ↓
③ 逐条列出分歧项（标记分歧类型：边界判定不一致 / 漏标 / 多标）
        ↓
④ 分歧讨论会（A + B + 第三方裁决人，一次会议，逐条过）
        ↓
⑤ 裁决结果写入 golden_set_v1.jsonl，并在 notes 记录：
     "原标注=<X>；复核标注=<Y>；仲裁结论=<Z>；分歧类型=<T>"
        ↓
⑥ 若 Kappa < 目标 → 回溯修订本规范 §六 判定标准 → 重检
        ↓
⑦ 定稿 golden_set_v2.jsonl（版本升级，不覆盖 v1）
```

| 仲裁规则 | 说明 |
|---|---|
| 裁决人 | 由第三名成员担任；若不可得，采用"**保守优先**"原则：分歧时取**更严格**的等级（L1 优先于 L2） |
| 记录留痕 | **禁止**直接覆盖原标注；分歧与仲裁过程必须可追溯 |
| 版本纪律 | 修订后**升版为 v2**，v1 保留；引用时须写明所用版本 |
