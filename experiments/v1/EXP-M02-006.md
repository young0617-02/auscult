## 四、本次发现的意义

1. **F2（补测点目录）在云端的收益 = +30.0pp** —— 首次在**云端**验证 F2 采纳形态，收益量级（+30pp）与本地 7B 四臂（+28.3pp）**高度一致** → **F2 采纳决策得到双向印证**。
2. **判据修正前的"云端 0.60"是题目缺条件导致的系统性低估**：补齐 `sensor_ids` 测点目录后，`参数值正确率` 由 **0.5882 → 0.9412**，`多轮` 33%→100%、`多工具` 50%→75%。
3. **M0.2 的阻塞已收敛为单点**：剩 **1 条用例 / 1 个档位**（无效拒绝），而非此前的"多档 No-Go"。
4. **多工具档已 Pass（75%）** —— 说明"云端单响应编排"在信息补齐后**可达成**（`plan/M02-V1-混合形态方案.md` §二 方案 A 得证）。

## 五、下一步（强假设）

**假设**：`v1-016` 属"拒止行为"，而**拒止对 system prompt 文本高度敏感**（`ISS-026`）。现有 `prompt v1` 仅 3 条 few-shot、**无拒止专项示例**。

**证据链**：

| 配置 | 拒止表现 |
|---|---|
| 本地 qwen + `prompt v2`（8 条 few-shot，含 2 条拒止专项） | **100%**（`EXP-V1-004`：拒止误调用 15→0） |
| 本地 qwen + `prompt v1`（3 条） | **0%**（`EXP-M02-002` 臂 A/D） |
| 云端 27B + `prompt v1`（本实验） | **67%**（2/3） |

→ **预期方案**：`EXP-M02-007` = **`tools_v4` + `prompt v2`**（唯一变量 = prompt 版本），20 用例 × 1。若拒止档达 ≥70% 且其余 4 档维持 Pass → **M0.2 翻 Pass**。

**约束**：当日 20 次预算**已用尽**（本实验用满）→ 执行前须按文档载明的方式**调锁**（`env/cloud.json` `budget_lock`）或**次日执行**。
