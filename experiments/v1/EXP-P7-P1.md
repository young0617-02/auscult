### 2.3 **必须一并登记的三个保留意见**（否则 15/15 会被误读）

1. **过拟合风险（最重要）**：smoke 的 5 条用例**就是**指引条款的写作对象（同一批失败簇），
   100% 只能说明「指引在自己针对的样本上生效」，**不能**外推为参数正确率。泛化只能由跳②（含 20 条主集中**未参与指引设计**的用例）回答。
2. **`v1-010` 出现步数膨胀**：steps = 9 / 8 / 7（基线 3–5），其中 R1/R2 触发强制收口。
   模型在 4 步上限内反复重查同一测点（`query_sensor` 被调 3–4 次）→ **参数对了，但循环效率变差**。
   该样本在判分上通过（判据只比对期望调用是否出现），但**成本与体验上是退步**，须在跳②计入 `Σ llm_calls` 观察。
3. **`top_k` 类只是「首调对了」**：`v1-014` 的后续探索轮仍会填 `top_k=10`；判分按首个匹配调用判定，故不影响通过。
   这说明指引改变的是**首调习惯**，不是「彻底不再补参数」。

### 4.5 唯一剩余失败（`v1-007` R1）

```
query_sensor {device_id: PUMP-A-01, sensor_ids: [vib_x,y,z], time_range: {start: 3d}, aggregation: "raw"}
→ 判分：参数值错：aggregation 期望 'max'，实际 'raw'
```

用例 lenient 允许 `trend`/`avg`（同轮 R3 填 `trend` 通过、R2 省略通过）。模型把「帮我查一下**实测数据**」
读成「要原始逐点序列」。**属语义边界，不是系统性缺陷**（1/75）：
提示词的 `aggregation` 条款只列了「趋势 / 最高 / 平均 / 超限次数 / 一起看一下」，**未覆盖「查实测数据」这类说法**。

→ 登记为 **P1.1 微调候选**（非本次范围）：`raw` 仅在用户明确说「原始值 / 逐点明细 / 整条曲线」时传；
「查实测数据 / 看看数据」不等于原始序列。

## 五、结论与处置

1. **跳① GO（15/15）→ 跳② 六档首次全绿（74/75 = 98.67%）**。
   **参数取值约定这一改动在本判据集上成立**：五类参数失败簇全部收敛（§4.3），无一例工具名错、零护栏违规、零错误样本。
2. **与 D2 同口径对照：87.3% → 98.67%（+11.4pp）**，且**成本下降**（调用 178 → 168、强制收口 35% → 16%）。
   即「少传参数」**没有**让诊断取证变差，反而让循环更早收口。
3. **是否「切默认」由所有者判决**。本实验提供的资格是：按设计口径（产品提示词 + 产品工具面 + 告警前置 + 默认 4 步）
   **首次六档全绿**。本实验**不**代替该判决，也**不**等于产品整体验收。
4. **唯一剩余失败 `v1-007` R1（`aggregation=raw`，1/75）** 登记为 P1.1 候选，**不构成回退理由**，
   也不影响多工具档（91.7% ≥ 70%）。
5. **结论边界**：单模型（`Qwen/Qwen3.8-27B`）、工具打桩、25 条判据、单日 3 轮。
   真机链路（真实 TDengine/Milvus/PG）**未验证**；U1 脱敏重审仍为上线前置；
   若决定切默认，建议先跑 `scripts/smoke_agent_cloud.py` 真机链路取证。
6. **归档**：`experiments/v1/raw/EXP-P7-P1-smoke-R{1,2,3}.jsonl(.meta.json)`、
   `EXP-P7-P1-smoke.agg.json`、`EXP-P7-P1-D2-R{1,2,3}.jsonl(.meta.json)`、`EXP-P7-P1-D2.agg.json`（只增不改）。
7. **一处保真度说明**：harness 的审计路径是**硬编码** `EXP-P7-GATE-D.security_audit.jsonl`（未改 harness，避免动被测面），
   故本次 75 个样本的 `tool_call` 审计**追加**在该文件末尾；如需按实验隔离，另立 P1 议题（改 `--audit` 参数）。
