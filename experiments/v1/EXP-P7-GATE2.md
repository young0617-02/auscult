### 1.2 判据前置说明（不构成放宽）

重释义**不是**「让用例变简单」，而是把考点从「产生写操作意图」纠正为「**不得在图内产生写操作**」——后者才是 ADR-007 与产品 Agent 工具面（4 个只读工具）的真实口径。反向证据：重释义后 `EXP-P7-GATE` 的 R2（唯一调用 `generate_report` 的一轮）**由通过转为失败**，即该口径对模型更严而非更松。

## 四、结论与处置

1. **判据未闭闸**：整体 No-Go（多轮 66.7%）。按预登记决策规则 → **不切默认**（默认维持 `deterministic`），与 `EXP-P7-GATE` 同结论、但成因不同。
2. **重释义本身是正确且更严的**（R2 的写操作调用由 ✅ 转 ❌，机制符合 ADR-007），但**它没能解决闸门问题**：真正的缺口是**被测对象与产品口径不一致** —— V1 harness 仍把 `generate_report` 作为可用工具交给模型（`tools_v4` 5 工具），而产品 Agent 只暴露 4 个只读工具。**只要工具面里有写操作，模型在"出报告"语境下就会去调它**（本次 3/3 实证）。
3. **本次相对 `EXP-P7-GATE` 的差异（同配置、唯一变量 = 用例重释义）**：首成 68/75 → 63/75；多轮 7/9 → 6/9。差异全部可由 `v1-019` 的口径切换解释，另有参数值错频次轮间波动（`v1-008`/`v1-010` 为 R1/R3、`v1-004`/`v1-009` 为 R1/R2，与 GATE 同类但分布不同）。
4. **下一步候选（须所有者判决，执行方不代为选择）**：
   - **路径 C（工具面对齐）**：让 harness 工具面 = 产品工具面（去掉 `generate_report`）。注意副作用：`v1-019` 的"产生写操作意图"考点随之**消失**（工具不存在则禁调判据变成空判），该用例需**整条替换**为真实多轮上下文考点（并重跑）。属**用例集二次修订 + 工具面变更**，影响面大于本次。
   - **接受 No-Go**：维持 `deterministic` 默认，登记"云端 Agent 形态未过 V1 判据闸门"，以异步诊断产品口径另行评估（U2）。

   > **✅ 已判决并执行（2026-10-20，所有者指示「先 C 拿到一版可信分数，同时立项 D」+ U2 判异步诊断）**：
   > 路径 C 已跑完 → `experiments/v1/EXP-P7-GATE3.md`（首成 89.33%、多轮 100%、单工具/多工具中间区间）；
   > 路径 D 已立项 → `docs/p7-design-gate-product-agent-2026-10-20.md`（未开工）；
   > U2 已判决「异步诊断 + 实时进度」→ `docs/p7-decision-async-diagnosis-2026-10-20.md`。
   > **本实验（GATE2）分数自此不再对外引用**（被测工具面含写操作，测非所测）。
5. **登记不修**：参数值错 5 类（`direction`/`window`/`fault_keywords`/`time_range`）记已知边界（P1 候选：产品 Agent 提示词可加参数默认值指引，但不得改冻结区 `prompts/`）。
6. **预算**：有效云端 51 次（作废轮 401 不计费）；当日累计 71 + 51 = **122/340**，未调锁。
