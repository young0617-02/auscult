## 三、`ISS-031`：判分器对非字符串 `aggregation` 崩溃（已修复）

### 3.1 现象与根因

`scripts/judge_tools.py::_aggregation_over_limit_equivalent` 原实现：

```python
return a in OVER_LIMIT_ALIAS and b in OVER_LIMIT_ALIAS
```

`OVER_LIMIT_ALIAS` 为 `set`，`in` 需要**可哈希**操作数；当模型把枚举包成 **dict / list** 时抛
`TypeError: unhashable type` → **判分器崩溃，整轮实验中断**。

### 3.2 复现条件与实测证据

- **调用 1 次** `qwen2.5:7b`（`v1-012`，输入"最近 30 天振动超限次数是多少？"）：
  ```json
  "aggregation": {"limit": 500, "type": "count_over_limit"}
  ```
  → 模型把枚举值包成了对象（而非字符串 `count_over_limit`）。
- **鲁棒性审计**（对 `{"value":...}` / `["avg"]` / `5` / `None` / `""` 逐一注入）：
  仅 `_aggregation_over_limit_equivalent` 崩溃（`duration_equivalent` / `_window_canonical` / `_is_superset` 均安全）；
  另发现同源的 `_aggregation_canonical`（同样 `value in OVER_LIMIT_ALIAS`）亦有隐患。

### 3.3 修复

两处均加**类型守卫**：非字符串一律**不算等价 / 原样返回**，交由后续精确比对判「参数值错」。

### 3.4 零回归验证（**关键**）

| 检查 | 结果 |
|---|---|
| 重判 `EXP-M02-010` ~ `-015` 与记录值比对 | ✅ **6/6 逐项一致**（修复对既有结论**零影响**） |
| 原崩溃输入（dict / list / int / None） | ✅ 全部判「参数值错」并给出可读信息 |
| 崩溃前已落盘的 33 条 | ✅ 可正常判分（首次成功率 0.5455） |
| `tests/` 回归测试 | ✅ 新增 13 用例（共 **119**），全绿 |

> **安全论证**：修复只把「异常」转为「False」，**字符串输入的判定路径逐字节未变**（已用全枚举组合交叉验证），
> 故**不构成判据口径变更**，无需重跑既有实验。

### 3.5 覆盖缺口（诚实记录）

该缺陷**未被发现于**：`judge_tools --selftest`、以及 2026-10-06 新增的 106 个回归测试
（当时只覆盖了**字符串**取值的等价判定）→ **由 H9 实跑暴露**。本次已补齐非字符串取值的回归测试。
