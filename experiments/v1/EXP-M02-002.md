## 一、实验设计与四臂口径

**目的**：F2 = 在 **schema 描述**与 **prompt 场景背景** 两处同步补齐「测点目录 + 轴向/驱动端映射」（根因 B：v1-005 / v1-010 / v1-013 属"任务信息不足"）。载体有两个，用多臂把载体效应分离，并加一条**确定性对照臂**排除运行间波动。

| 臂 | 实验 ID | prompt | schema | 说明 |
|---|---|---|---|---|
| **A（基线）** | EXP-M02-002 | `tool_call_prompt_v1.md` | `tools_v2.json` | 与 EXP-M02-001 同条件（除模型/端侧） |
| **B（F2 完整）** | EXP-M02-003 | `tool_call_prompt_v3.md` | `tools_v4.json` | 两处载体同时补齐 |
| **C（仅 schema）** | EXP-M02-004 | `tool_call_prompt_v1.md` | `tools_v4.json` | 只补 schema 描述，prompt 保留 v1 原文 |
| **D（确定性对照）** | EXP-M02-005 | `tool_call_prompt_v1.md` | `tools_v2.json` | **逐字重跑臂 A**：A≡D 则管线可复现，A≠D 则存在运行间波动 |

**共同固定参数**（仅 prompt / schema 两处变量不同）：

| 项 | 值 |
|---|---|
| 模型 / endpoint | `qwen2.5:7b` @ `http://127.0.0.1:11434/v1/chat/completions`（本地 Ollama） |
| 用例集 | `evals/v1_cases.jsonl`（20 条：单工具 6 / 多工具 4 / 参数校验 4 / 无效拒绝 3 / 多轮 3） |
| repeat / max_retry | 3 / 3 |
| 约束解码 | ON（`--constrain`，GBNF；`expect_reject` 用例不施加数组语法） |
| 固定参数 | temperature=0.0 / seed=42 / num_ctx=8192 / top_p=1.0 / max_tokens=1024 / stream=false |
| 云端调用 | **0 次**（不触及 `env/cloud.json` 的 per-day 预算锁） |

> **口径提示（如实呈报）**：判分器 `5_首次成功率` 的实现是对 `attempt==1` 的全部 repeat 记录按 `case_id` **后者覆盖前者**取值（即取末次 repeat 的首轮），与 `3_参数值正确率` 的"3 次平均"口径不一致。故本记录以 **3 次平均首轮通过率**为主口径，并同时给出判分器口径，避免单一口径误导。

**执行前置**：`llm_adapter.py`（F1）、`judge_tools.py`（F4/F5/F6）自检双双通过；prompt/schema 由 `run_v1.py` 经 `LLMAdapter(schema_path=args.schema, prompt_path=args.prompt)` 正确穿线（schema → 程序化注入 System Prompt；prompt → few-shot 同源），**无隐藏差异**。

## 三、机制级实证（F2 直接效应，可确证）

`query_sensor.sensor_ids` 原始取值（`attempt=1`，3 次 repeat 全列）：

| 用例 | A 基线 | C 仅 schema | B 完整 |
|---|---|---|---|
| v1-005 | `['...temp_drive']` ×3 → **0/3** | `['...temp_bearing_de']` ×3 → **3/3** | `['...temp_bearing_de']` ×3 → **3/3** |
| v1-010 | `[vib_x,vib_y,vib_z,temp_drive]` ×3 → **0/3** | `[vib_x,vib_y,vib_z,temp_bearing_de]` ×3 → 0/3 | 同 C → **3/3** |
| v1-013 | `[vib_z,temp_drive]` ×3 → **0/3** | `[vib_z,temp_bearing_de]` ×3 → **3/3** | 同 C → 0/3 |

1. **幻觉别名 `temp_drive` 被清零，且 3/3 双向稳定**：A 上三条用例 **9/9 次**输出模型自造的 `temp_drive`；C 与 B 上 **9/9 次**输出规范名 `temp_bearing_de`。这是"任务信息不足"根因的直接证据，**且证明 schema 描述单独即可达成修复**——prompt 侧补齐（v3）对该机制**非必要**。
2. **v1-010 / v1-013 的残余差异与测点无关**：C 的 sensor_ids 已正确，其 v1-010 仍失败（`aggregation` 期望 `avg`、实际 `trend`）；反之 B 的 v1-013 失败（期望 `avg`、实际 `max`）。同一"aggregation 歧义"在 C/B 上**方向相反**，属**用例歧义 + 运行敏感性**叠加，不是测点目录问题。
3. **v1-010 的"超集"不构成问题**：模型多带 `vib_y/vib_z`，判分口径为"期望 ⊆ 实际"，故只受 `aggregation` 影响。

## 四、非机制翻转（**不得作为能力结论**）

| v1-010 | 多工具 | 0/3 | 0/3 | 0/3 | 3/3 | B>C |

- **v1-015 原始证据**：A 在 3/3 次都**照抄 few-shot 示例 2 的调用**（`search_knowledge("离心泵振动烈度限值 7.1 mm/s 评价标准")` + `query_sensor(vib_x)`）——**示例泄漏**，属拒止类脆弱点；C/B 上消失。
- **v1-008 原始证据**：A 给 `fault_keywords=["振动"]`（期望含"轴承"→覆盖不全判错）；B **完全不填** `fault_keywords`（按 notes"缺省亦可接受"→判对）→ **判据漏洞**，与 F2 无关。
- **A vs C 中的"非机制翻转"（v1-013/015/016/017/020）共用同一特征**：与测点命名语义无关。臂 D 已验证 A **可复现** → 故该差异**不是"坏运行"**，而是"该管线对 system prompt 文本存在**确定性但脆弱的敏感性**"。因此它**既不能归因于测点目录机制**（语义无关），也**不能作为"F2 有效"的证据**（不可迁移）。

**观察项（本次不放宽，登记待复审）**
- **OBS-F2-1（v1-008 口径漏洞）**：给部分关键词判错、完全不填判对 → 激励模型少填参数。
- **OBS-F2-2（v1-013 / v1-010 aggregation 歧义）**：与 F3/F5 同类，列入用例复核候选。
- **OBS-F2-3（few-shot 示例 2 泄漏）**：删工单请求被套用示例 2 调用，拒止类脆弱点。
- **OBS-F2-4（管线复现性）→ 已闭环**：臂 D 与臂 A **逐用例一致 19/20**（唯一差异 v1-008：A 0/3、D 1/3，且 B 亦为 1/3）、3 次平均 0.4667 vs 0.4833（差 1/60 次）；且 A/D 在**无效拒绝上同为 0/9**。→ **`temperature=0` 下该管线可复现，臂 A 不是"坏运行"**。判分侧伪因亦已排除（交叉判分）：C 的 raw 改用 `tools_v2` 判 → 仍 0.75 / 无效拒绝 100%；A 的 raw 改用 `tools_v4` 判 → 仍 0.45 / 0%。**故 A vs C 的差异是真实的生成侧差异。**

## 五、载体归因（定论）

| 对比 | 含义 | 结果 |
|---|---|---|
| A vs D | 同配置重跑（复现性对照） | 0.4667 vs 0.4833，逐用例 19/20 一致 → **可复现** |
| A vs C | 仅 **schema 描述** 变化 | 3 次平均 **0.4667 → 0.7500**（+0.283） |
| C vs B | 仅 **prompt 场景背景** 变化 | **0.7500 → 0.6667**（−0.083）：prompt v3 **无增益**，且在 v1-013/016/017 上更差 |
| A vs B | F2 双载体合并 | 0.4667 → 0.6667（+0.20） |

**定论**
1. **F2 的采纳形态 = 只补 schema 描述（`schemas/tools_v4.json`），prompt 保持 v1。** 依据：机制修复在 C 上即已达成（3/3 稳定），且 C 的整体首轮（0.75）高于 B（0.667）；prompt v3 的场景背景变更**未带来增益**，在拒止类上表现为负。
2. **`prompts/tool_call_prompt_v3.md` 不采纳为生产提示词**（文件保留并标注"未采纳"，供审计追溯；与 P5 `tools_v3.json`（简化版、负结果保留）同处置口径）。
3. **附带效应须如实标注**：A→C 的抬升**不止**测点命名（v1-005/010/013），还含 **v1-013/015/016/017/020** 等与测点语义无关的用例；其成因**未能由机制解释**（拒止类 `0/9 → 9/9`），只能定性为"system prompt 文本条件化副作用"。该效应在本配置内可复现，但**不可迁移**（换用例/换模型未必复现），**不得**作为能力结论或"F2 有效"的证据。
