## 一、现象

在 `paradedb/paradedb`（pg_search 0.25.10）上创建 `USING bm25` 索引后 `INSERT` 报：

```
No key field defined
```

此前多路径复现（`key_field`+`text_fields`、不同索引名、先插数据后建索引、空表建索引）均失败，导致 V2 稀疏对标长期悬置，pgvector 侧降级使用 tsvector。

---

## 二、排障过程

### 2.1 逐步收敛（本轮实测）

| # | 尝试 | 结果 |
|---|---|---|
| 1 | 最小复现：建表+插数+`CREATE INDEX ... USING bm25 (chunk_id, text) WITH (key_field='chunk_id', text_fields={'text':{language:chinese, tokenizer:zhparser}})` | **text_fields JSON 引号被 shell 转义破坏 → 语法错**；改 SQL 文件传输后 → `SearchFieldConfig::text: a 'type' must be passed` |
| 2 | tokenizer 配 `{type:chinese}` | `unknown tokenizer type: chinese` |
| 3 | tokenizer 配 `{type:zhparser}` | `unknown tokenizer type: zhparser` |
| 4 | `paradedb.tokenizer('chinese')` 构造成功但 `tokenize()` 运行时报 unknown | 确证：**pg_search 0.25.10 镜像未内置 chinese/zhparser 运行时** |
| 5 | 枚举可用 tokenizer：`whitespace`/`ngram`/**`stemmer`(no)** | whitespace、ngram 可用；stemmer 不可用 |
| 6 | ngram 未配 `prefix_only` | `ngram tokenizer requires a boolean 'prefix_only' field` |
| 7 | **`tokenizer:{type:'ngram', min_gram:2, max_gram:3, prefix_only:false}`** | ✅ **建索引 + INSERT 成功 + 中文词检索召回正常** |

### 2.2 根因结论

1. **`key_field` 必须正确地指向表的主键列**（`chunk_id text PRIMARY KEY`），否则插入新行无法定位 → `No key field defined`。
2. **镜像内 pg_search 0.25.10 未内置中文语义 tokenizer**（`chinese`(jieba) 与 `zhparser` 的运行时均 `unknown`）。此前悬置大概率是把可用 tokenizer 误判为"中文分词失效即 BM25 不可用"。
3. **`ngram(2,3)` 可对中文做子串召回**，且必须显式 `prefix_only=false`。

## 三、最终有效 SQL（正解）

```sql
CREATE TABLE tmp_bm25_test (chunk_id text PRIMARY KEY, text text);

CREATE INDEX tmp_bm25_idx
  ON tmp_bm25_test
  USING bm25 (chunk_id, text)
  WITH (
    key_field = 'chunk_id',
    text_fields = '{"text": {"type": "text", "tokenizer": {"type": "ngram", "min_gram": 2, "max_gram": 3, "prefix_only": false}}}'
  );

-- 检索（`@@@` 是 pg_search BM25 查询算子）
SELECT chunk_id, paradedb.score(chunk_id)::numeric(6,4) AS score
FROM tmp_bm25_test
WHERE text @@@ '离心泵'
ORDER BY paradedb.score(chunk_id) DESC;
```

**实测召回**：查询「离心泵」→ c5(1.84)、c3(1.57)、c1(1.32)，score 递减，中文索引命中正常。
