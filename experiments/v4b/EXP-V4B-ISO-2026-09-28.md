# EXP-V4B-ISO-2026-09-28：V4b 分组启动稳态峰值隔离实测

> **目的**：把 `reports/v4b-report.md` §12.4 中"留待 P1 的分组启动稳态峰值实测"拉回本案，实际拉起 base 四档，量测稳态峰值，核算 24GB 门禁线（口径 B）。
> **隔离方式**：`docker/compose.v4b-iso.yml` 端口重映射 PG→15432、Redis→16379（`!override`，docker compose v2 对 ports 默认追加、须强制替换），避开 iotao-tsdb-lite(5432)/iotao-redis-lite(6379)；容器名 `auscult-*` 与 `auscult-v2-*` 不冲突。**不动任何 v2 / iotao / smart-doc / nacos 容器。**
> **口径**：判据对象 = 宿主总占用（口径 B，用户 2026-09-28 确认定稿）。**注意**：本机组含多项目共存，宿主总占用无法干净归属本系统，故同时给出「本系统 V4b 自身足迹」与「宿主实测」两栏。
> **日期**：2026-09-28 ｜ 命令 cwd = 项目根。

- 全栈 8 容器同时峰值 = 14.99+76.92+144.3+26.57+5.95+932.1+211.1+5.85 = **1417.78 MiB ≈ 1.39 GiB**

## 二、LLM 侧（宿主 Ollama）

- 实测 `ollama ps`：**当前无 7B 常驻**（裸表）。
- 显存 `nvidia-smi`：已用 1477 MiB / 总 8188 MiB（8GiB）。
- §6.1 既有数据（沿用，未重测）：双 7B ≈11.6GiB 不可同日驻留（> 8.2GiB）；单 7B + BGE-M3 临界共存。**双 7B 错峰实测仍留待 P1**（本案未加载模型，避免占用农场态内存）。

## 三、判据核算（口径 B）

| 口径 | 数值 | vs 24GB | 结论 |
|---|---|---|---|
| 本系统常驻核心（容器） | ≈0.26 GiB | ✅ 远低于 | 分组启动核心仅占 1% 余量 * |
| 本系统全栈同时峰值（容器） | ≈1.39 GiB | ✅ 远低于 | 分组启动后容器侧绰绰有余 |
| 本系统 + 单 7B（§6.1 ≈6GiB） | ≈7.4 GiB | ✅ 低于 | 满足门禁 |
| 宿主实测（含多项目共存） | 已用 27.66 / 总 31.8 | ⚠️ 超线 | 由 iotao/smart-doc/nacos/v2 共同贡献，**非 V4b 独占** |

> **结论**：分组启动策略使**本系统自身 V4b 足迹（全拉 1.39GiB + 单 7B ≈7.4GiB）远低于 24GB 门禁线**。宿主 24GB 线在**多项目共存**下无法干净归属本系统；若主机为本系统专用，分组启动 + 单 7B 后峰值 ≈7.4GiB < 24GB，**中间区间处置成立且余量充足**。V4b 维持"中间区间（分组启动+按需加载）"，不升 Pass（宿主总占用含共存因子，且双 7B 错峰未实测）。
