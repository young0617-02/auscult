## 一、结论先行

1. `EXP-M02-001` 的 8 条失败中：**6 条判为口径/信息类问题**（1 条 adapter 实现缺陷 + 3 条任务信息不足 + 2 条判据过严/歧义 + 1 条判据严于规格，v1-010 兼跨），**1 条为明确模型错**（v1-016 幻觉），**0 条**因阈值问题失败。
2. **"参数值语义是跨模型共同瓶颈"得以验证**：同类失败（query 语义、evidence_refs、aggregation、sensor_ids）在本地全部历史实验中稳定复现（§三）。
3. **"口径修正即可 Pass"已被重判证否**：F1/F4/F5/F6 落地后，**19 组（11 实验）首次成功率普遍上升（+0.05~+0.12），但整体档位无一翻为 Pass、单工具档全部仍 No-Go**（§六）。
4. **M0.2 维持 No-Go**，但**归因须从"模型能力不足"修订为"判据口径缺陷 + 任务信息不足 + 模型部分错"的混合归因**（对应风险 `R-V1-7`、缺陷 `ISS-025`）。
5. **F2 重测（四臂）**：机制修复确证且 **`schema` 描述单独即充分**（`temp_drive`→`temp_bearing_de`，3/3 稳定）；**采纳形态 = 只补 `schemas/tools_v4.json`、保留 prompt v1**，`prompt v3` 不采纳；四臂整体档位**全部仍 No-Go** → **M0.2 维持 No-Go**（§七.1）。臂间抬升中含**不可迁移的提示词条件化副作用**，已按纪律**不作能力结论**（`ISS-026`）。

> 原则：**证据不足不动；阈值不动；D 类不动。**

| # | 对象 | 现象 | 原判据为何错 | 建议 | 影响面（预估，待 §六 重判确认） |

1. **F2 机制修复确证，`schema` 描述单独即充分载体**：v1-005 / v1-010 / v1-013 的幻觉名 `temp_drive` 在 A/D 上 **9/9 次**出现，在 C/B 上 **9/9 次**变为规范名 `temp_bearing_de`（3/3 稳定）。→ **prompt 侧补齐（v3）对该机制非必要**。
2. **F2 采纳形态 = 只补 schema（`schemas/tools_v4.json`），保留 `prompt v1`**：C（0.7500）> B（0.6667）；`prompts/tool_call_prompt_v3.md` **不采纳为生产提示词**（文件保留并标注"未采纳"，供审计追溯）。
3. **复现性与归因纪律（关键）**：臂 D（逐字重跑 A）与 A **逐用例一致 19/20**（唯一差异 v1-008），且 A/D 无效拒绝**同为 0/9** → **管线在 temperature=0 下可复现**；交叉判分再排除判分侧伪因（C 的 raw 用 `tools_v2` 判仍 0.75 / 拒止 100%；A 的 raw 用 `tools_v4` 判仍 0.45 / 0%）。故 A→C 的抬升属**真实生成侧差异**，但**影响面超出测点命名机制**（连与测点无关的 v1-016 缺设备号、v1-017 寿命预测也从 **0/9 → 9/9**）→ 只能定性为 **"system prompt 文本条件化副作用"**：本配置内可复现，**不可迁移**，**不得**作为能力结论或"F2 有效"的证据。

**M0.2**：四臂**整体档位全部 No-Go**（最差档：单工具 0.67 / 多工具 0.25–0.33 / 无效拒绝 0.00–0.33）→ **M0.2 维持 No-Go**，阻塞项仍为 V1 工具调用（单工具档 + 多工具档 + 拒止档）。

**新增观察项（登记，本次不放宽）**：`OBS-F2-1` v1-008 判据漏洞（部分关键词判错、完全不填判对）；`OBS-F2-2` v1-013/v1-010 `aggregation` 歧义（与 F3/F5 同类）；`OBS-F2-3` few-shot 示例 2 泄漏（删工单请求被套用示例 2 调用）；`OBS-F2-4` 拒止行为对 system prompt 文本高度敏感 → 已登记 `ISS-026`。
