## 一、实验目的与范围

### 1.1 核心目标

在**固定部署形态 + 固定 Schema v1** 的前提下，产出 **`模型 → 角色` 映射表**，回答：

> 本地 7B 级模型到底能不能可靠地"调用工具"？如果不能，哪些角色必须交给云端？

### 1.2 范围边界（防范围蔓延）

| 项 | 范围 |
|---|---|
| **在范围内** | 工具选择 / 参数生成 / 无效请求拒绝 / 重试鲁棒性 / 延迟 / 输出冗长度；两模型 + 云端上界校准 |
| **不在范围内** | 检索质量（→ V2）、时序接入（→ V3）、长流程可靠性（→ V5）、模型微调、量化方案对比（仅在胜出者上做 Q8/FP16 复核） |
| **固定项（不得中途更改）** | Tool Schema v1（`schemas/tools_v1.json`）、部署形态、Prompt v0、`num_ctx`、`temperature` |
| **可调项** | Prompt 版本（v0 → v1 的演进是本项产出之一）、重试次数（上限 3）、约束解码开关 |

### 1.3 主场景对齐

20 条用例全部围绕 **"离心泵轴承振动异常诊断"** 构造，覆盖真实诊断链路中会出现的工具调用形态，避免用玩具用例得出过于乐观的结论。

## 三、实验设计

### 3.1 设计矩阵

| 组 | 模型 | 用例数 | 重复次数 | 目的 |
|---|---|---|---|---|
| 主组 A | `qwen2.5:7b` | 20 | 3 | 主结论 |
| 主组 B | `deepseek-r1:7b` | 20 | 3 | 主结论（含 `think` 剥离处置） |
| **上界校准组** | `Qwen/Qwen3.8-27B`（ModelScope，endpoint `api-inference.modelscope.cn`） | 20 | **1** | 给出"这道题的天花板在哪"，用于判断本地差距是"模型能力问题"还是"任务本身不可做" |

- 总调用次数：`20×3 + 20×3 + 20×1 = 140` 次。
- **`think` 处置**：`deepseek-r1` 先剥离 `think` 段，**再做 JSON 判定**（顺序不可颠倒，否则会把思维链里的 JSON 误判为工具调用）。
- **冷/热启动区分**：每组第一次调用记为冷启动，其后记为热启动；延迟指标分开统计。

### 3.2 用例库（T2.1）

**产出**：`evals/v1_cases.jsonl`，20 条，每条含：

| 字段 | 说明 |
|---|---|
| `case_id` | 唯一编号 |
| `type` | 5 类型之一：**单工具 / 多工具 / 参数校验 / 无效拒绝 / 多轮** |
| `difficulty` | 难度分层：易 / 中 / 难 |
| `input` | 用户输入（对齐离心泵轴承振动诊断场景） |
| `expected_tool_calls` | 期望的工具名 + 参数 |
| `expect_reject` | 是否应被拒绝 |
| `notes` | 判分要点 |

**5 类型覆盖要求**（每条用例只归一类，20 条须覆盖全部 5 类）：

| 类型 | 考察点 | 条数 |
|---|---|---|
| 单工具 | 工具名选对 + 必填参数齐 | **6** |
| 多工具 | 需要串联/并行多个工具 | **4** |
| 参数校验 | 枚举值、ID 精确匹配、`time_range` 相对区间 | **4** |
| 无效拒绝 | 该拒绝时不调用（信息不足、超范围） | **3** |
| 多轮 | 上下文补全，前一轮澄清后本轮调用 | **3** |
| **合计** | | **20** |

> 实际条数取自 `evals/v1_cases.jsonl` 逐条统计（编号 `v1-001` ~ `v1-020`）。
> 难度分布：易 3 / 中 9 / 难 8。工具覆盖：`query_sensor` 9 / `search_knowledge` 5 / `get_maintenance_history` 4 / `query_graph` 2 / `generate_report` 1。

### 3.3 自动判分器（T2.2）

**产出**：`scripts/judge_tools.py`，判分逻辑：

1. **工具名精确匹配**：`tool_calls[0].name` vs 期望名；
2. **JSON Schema 校验**：参数是否符合 `schemas/tools_v1.json` v1；
3. **参数值比对**：
   - 枚举 / ID → **精确匹配**；
   - `time_range` → **±10% 语义等价**（如"最近 1 小时" vs "最近 60 分钟"视为等价）；
4. **重试计数**：记录第几次成功；
5. **失败归类**：工具名错 / JSON 不可解析 / 参数缺失 / 参数值错 / 该拒绝却调用 / 该调用却拒绝。

### 3.4 统一适配层（T2.3）

**产出**：`scripts/llm_adapter.py`

- 单一入口适配两模型，走 **OpenAI 兼容 `/v1/chat/completions`**；
- **统一剥离 `think`**（唯一剥离点，防止两模型口径不一致）；
- **对缺失 `tool_calls` 的响应显式标记**（`scripts/llm_adapter.py` 置位 `AdapterResult.tool_calls_missing`，判分器据此记 `格式退化` 并单独计数）—— 应对"Ollama 静默退化"（见 §八 R-V1-3）。

### 3.5 落盘与执行（T2.4）

**产出**：`scripts/run_v1.py`（原始请求/响应 JSONL + 汇总表 + **断点续跑**）

```bash
# D2 下午 – D3：主组（2 模型 × 20 用例 × 3 次）
python scripts/run_v1.py --models qwen2.5:7b,deepseek-r1:7b --repeat 3 --out experiments/v1/raw/results.jsonl

# 上界校准（云端 × 20 × 1）
python scripts/run_v1.py --models "Qwen/Qwen3.8-27B@https://api-inference.modelscope.cn/v1" --repeat 1 --tag baseline_cloud --out experiments/v1/raw/EXP-V1-002.jsonl
```

### 3.6 实验登记（强制）

每次执行按 `docs/experiment-log-template.md` 登记：**digest / seed / prompt 版本 / `num_ctx` / `temperature` / commit**；原始数据落盘 `experiments/v1/raw/`，可追溯、可断点续跑。

## 五、分工决策（已定稿，落点 `docs/role-decision.md`）

**决策表**（按 2026-09-28 三路实测回填，结合云端上界 0.60）：

| 角色 | 建议承载模型 | 依据指标 | 中间区间处置 |
|---|---|---|---|
| 工具调用 / 参数生成 | 本地 7B 为**候选**（约束解码后链路稳定，可解析率 1.00）；最终承载待用例/Schema 复审后再定 | 首次成功率、参数值正确率 | 约束解码已消除格式退化；首次成功率未达 Pass，云端上界 0.60<0.90 → **用例/Schema 需复审** |
| 诊断推理 / 结论撰写 | 本地 7B 候选（qwen 多轮 0.67 / deepseek 无效拒绝 0.78，分层相对较好） | 首次成功率 + 分层结果 | 结合分层数据，按流区分派 |

## 七、判据与中间区间处置

### 7.1 判据（逐字采用上游计划）

| 判定 | 条件 |
|---|---|
| **Pass** | **首次成功率 ≥90% 且可解析率 ≥95%** |
| **中间区间** | **70–90%**：约束解码 + few-shot；仍不达标 → "本地推理 + 云端工具调用" |
| **No-Go** | **两模型均 <70% → 云端工具调用转正** |

> 判据适用对象：**首次成功率**（不是重试后成功率）。重试后成功率作为辅助指标报出，不作为过闸依据。

### 7.2 中间区间（70–90%）处置预案（**已定稿**）

判定落入 70–90% 时，**必须执行以下动作并记录代价**，不得直接放行：

| 步骤 | 动作 | 成功判据 | 若仍不达标的代价标注（必填） |
|---|---|---|---|
| ① | **约束解码**（按 `schemas/tools_v1.json` 强制 schema 约束输出） | 首次成功率回升至 ≥90% | 记录是否引入"合法但语义错"的参数（可能推高 4b 应调用却拒绝率）；标注对端到端 P95 的影响 |
| ② | **few-shot 补强**（在 Prompt 中加 3–5 个对齐主场景的示例） | 首次成功率 ≥90% 且可解析率 ≥95% | 记录 prompt token 增长 → 对延迟与 `num_ctx` 的挤占；标注对 P95 的影响 |
| ③ | ①② 后仍不达标 | — | 转 **"本地推理 + 云端工具调用"** 混合形态：本地做推理，工具调用交云端 |
| ④ | 转混合形态后 | — | **必须显式标注代价**：离线可用性下降、调用成本、P95 延迟上升、数据出域合规影响 |

> **纪律：中间区间 ≠ 通过。** 每条处置必须留下"做了什么 + 代价是多少"两行记录，写进 `docs/role-decision.md` 与 `reports/P0-summary.md` 的中间区间处置记录。

> **⚠️ 口径统一（2026-09-29 裁定）**：本表是**两步加固 + 两步兜底**的**精简表述**，缺少"③ Schema 简化"这一级。
> 权威清单以 `docs/role-decision.md` §四 的**四步**为准：① 约束解码 → ② few-shot 扩容 → ③ **Schema 简化（须升 Schema 版本）** → ④ 降级为混合形态。
> 裁定记录见 `reports/P0-summary.md` §3.3 / §6.1；**引用处置步骤数时不得使用"两步"版本**。

### 7.3 No-Go（<70%）备选路线

**两模型均 <70% → 云端工具调用转正。**

一旦触发，须同步评估并落盘：

1. 架构形态从"本地优先"改为"云端工具调用"；
2. 对数据出域合规的影响（与 `docs/data-sources-v1.md` 的合法性判定联动）；
3. 对 MVP 范围的影响（须同步修订 `docs/scope-mvp.md`）；
4. 对 P95 延迟与成本目标的影响（须显式标注，禁止"降级后仍宣称原指标"）；
5. **云端约束解码重测（EXP-V1-005，2026-09-28）**：云端走约束解码（`response_format json_schema` 结构化输出，ModelScope `Qwen/Qwen3.8-27B`，20×1）首次成功率 **0.55**（裸跑 EXP-V1-002 为 **0.60**）、可解析率 **0.8824**、参数值正确率 **0.5294**、多工具 **50%**。与裸跑双向口径对等（约束 + few-shot）下，云端仍**远低于 90% 单线** → 支撑「判据按类型分档重校」。
   **架构决策 = 云端工具调用转正 + 多工具架构切分（方案B：拆单工具多次调用/多轮）**，见 `docs/role-decision.md` §4.6。
   **分工口径重校（2026-09-28，收回"整线/全上云"过度外推）**：V1 判据只测 R-2/R-3（工具调用规划 + 参数抽取）；本地两模型单工具 33%/28%、参数校验 75%/50%、多轮 67%/67% 均未过 85% 线、多工具 0% → **R-2/R-3 工具调用上云（整线转云）**；但**非全上云**——R-4 证据归纳/诊断推理（合规锁死本地）、R-1 意图识别、R-5 审核摘要、检索+向量化、写操作/审计、有效拒绝边界（qwen 100%）、降级/离线兜底（Must #12）**保持本地**。**R-4 本地证据归纳/诊断可用性 = 新增未验证项（ISS-014）**，现值 0.67 为多轮工具调用分、非证据归纳分，待 P1 专项测试。（**ISS-014 已于 2026-09-29 闭环：EXP-R4-001 六维全 Pass，R-4 本地归纳/诊断可用，见 `role-decision.md` §6.1**）

### 10.4 参数归一化纠错量化（EXP-V1-NORM，2026-09-28）

> 背景：project-overview §8.2.1 建议 V1 破局优先做「参数归一化纠错（对 time_range / 设备号做规则后处理）」。
> 疑问：归因 §4.4 显示多数「参数值错」为**语义选择错误**（window/aggregation/relation_type…），仅极少数属格式类误差——
> 白名单归一化能否真正抬首次成功率，需量化验证，避免空耗或超额归一化掩盖真实缺陷。
> 详见 `experiments/v1/EXP-V1-NORM.md`。

- **新增载体**：`scripts/param_normalizer.py`（白名单归一化层，3 条确定性规则）+ `judge_tools.py --normalize`
  （判分比对前对 actual 应用归一化；`schema_valid`/`first_tool_match` 仍基于原始调用——格式门槛不放宽；不改 `raw` 数据）。
- **归一化白名单**（仅此 3 条）：R1 `time_range` 相对时长单位别名（`24小时`→`24h`、ISO 绝对时间不动）；
  R2 `device_id`/`sensor_id` 等 **仅 trim/去空白**；R3 数字字符串→number。
  **明确不做**：相对↔绝对时间转换、任何语义/枚举字段映射、多工具缺失补全。
- **评测**：对 EXP-V1-004（few-shot+拒止，2026-09-28）用 `--normalize` 重判：
  - **217 条记录逐条 diff，`success`/`call_issues` 变化 0 条；uplift = 0**。
  - 指标不变：qwen 首次 **0.50**/参数值 0.4118、deepseek **0.35**/0.3333；判据仍 **No-Go**。
- **关键修正（教训）**：首次实现曾对 `sensor_ids` 做**大小写规整**，重判**回退**（qwen 0.50→0.40）——黄金集
  `sensor_ids` 为小写、`_is_superset` 比对大小写敏感，归一化把合法小写 actual 与小写期望拆开导致误判。
  已修正为**保中性**（仅 trim/去空白）后 0 回退、0 提升。**结论：归一化必须是对比较器的中性变换**。
- **结论与处置**：参数归一化纠错 **uplift=0**，不构成 V1 破局手段；首次成功率瓶颈确在**参数语义选择 + 多工具编排**。
  归一化层保留为生产入参 canonical 化工具（P1 可复用），评估路径转 `docs/role-decision.md` §四 ③（Schema v2 简化）/
  ④（混合形态）+ 多工具编排评估。
