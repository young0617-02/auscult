# R-4 本地证据归纳/诊断专项测试（ISS-014）

## Context（为什么做）

P0 收尾时 V1 判据只测工具调用（R-2/R-3），**R-4「读证据→写根因/结论→带 evidence_refs 引用」的本地可用性毫无实测**。ISS-014 已登记为 P1 专项测试。当前 `role-decision.md` 中 R-4 的 0.67 实为多轮工具调用分、非证据归纳分，**不得据此宣称 R-4 本地可用**。

合规锁死：R-4 必须本地执行（宿主 Ollama `127.0.0.1:11434`），云端仅传脱敏摘要与结构化参数、不传证据原文。故本测试做**本地纯生成型归纳评判**，不落库、不转云，只判模型产出的 `generate_report` 归纳结构是否**结论正确 + 引用忠实（零幻觉）**。

**用户已确认**：20 条用例 / 仅 qwen2.5:7b / 采纳建议判据档位（结构≥90%、幻觉=0红线、覆盖≥70%、根因≥70%、severity≥70%、动作非空≥90%）。

## 用例结构 `evals/r4_cases.jsonl`（20 条）

每条一个证据包：`case_id / type / difficulty / device_id / scenario / evidence[] / golden`。

- `evidence[]`：每条 = `{id(如 E-001), type, ref, kind(real|distractor|fabricated), content}`；每包 5–9 条
  - **real**：根因支撑证据（振动时序 + 标准条款 + 维修记录 + 图谱因果）
  - **distractor**：真实但无关（如温度正常）——过度引用→忠实性扣分非幻觉
  - **fabricated**：包外伪造项——命中→幻觉硬失败（红线）
- `golden`：`root_cause_keywords[]`（must_have 全含才判定根因正确）、`expected_refs[]`（必须引用）、`distractor_refs[]`、`fabricated_must_not_refs[]`、`severity`、`recommended_actions_nonempty=true`
- 类型覆盖：sensor-only / knowledge-only / graph+maintenance / multi-source / distractor-trap / fabrication-trap

**自检强制不变量**：每包 ≥1 real + ≥1 distractor + ≥1 fabricated；包内 ref 全局唯一；expected_refs⊆real、fabricated_must_not_refs⊆fabricated、distractor_refs⊆distractor；device_id 匹配 `^[A-Z][A-Z0-9-]{2,31}$`。

## 判分 `scripts/judge_r4.py`

```python
# 关键函数
load_r4_cases() / validate_case_invariants()
inject_report_schema()          # 注入 generate_report.parameters
load_r4_system_prompt()         # 替换 {{REPORT_JSON_SCHEMA}}
load_r4_fewshot() / build_r4_messages()
parse_report_args()             # 抽第一个含 diagnosis_summary 的对象
judge_case(case, output, result) -> dict
aggregate() / verdict() / write_summary_csv()
_selftest() / main(--raw --cases --schema --prompt --out --detail-out --selftest)
```

**单条判定**：`structure_ok`（字段齐全+枚举合法）& `citation_honest`（cited ⊆ real_refs，**零幻觉/零包外**）& `coverage_ok`（expected_refs 全覆盖）& `root_cause_ok`（must_have 关键词全含）& `severity_ok` & `actions_ok` → `success`。

**失败归类（互斥，按优先级）**：结构退化 → 引用幻觉 → 证据漏引 → 根因错 → severity错 → 建议动作空。

**汇总维度（分子/分母分行）**：结构可解析率、根因正确率、引用忠实率、**幻觉率（红线单列）**、证据覆盖率、severity匹配率、动作非空率、首次成功率、重试后成功率、平均/P95延迟、输出token、think占比、失败分布、分层难度。

## 判据档位（`gate-criteria.md` §3.7，判据对象 = 首次成功率）

| 维度 | Pass | 中间 | No-Go |
|---|---|---|---|
| 结构可解析率 | ≥0.90 | 0.70–0.90 | <0.70 |
| **引用忠实（幻觉率）[红线]** | **幻觉率=0** | **0<幻觉≤0.15** | **>0.15** |
| 证据覆盖率 | ≥0.70 | 0.50–0.70 | <0.50 |
| 根因结论正确率 | ≥0.70 | 0.50–0.70 | <0.50 |
| severity 匹配率 | ≥0.70 | 0.50–0.70 | <0.50 |
| 建议动作非空率 | ≥0.90 | 0.70–0.90 | <0.70 |

**整体 = 有数据维度的最差档位**（任一 No-Go→整体 No-Go；恰一中间→中间区间；全过→Pass）。
**No-Go 处置（合规锁死，禁止转云传证据原文）**：① 回灌闭环重测幻觉；② 提示词/few-shot 加固（负样本）新开 experiment_id；③ 动态 grammar 约束 ref 集合【待实测】；④ 换更大本地量化模型。中间区间必留"做了什么 + 代价（Recall@5 无影响 / P95【待实测】）"两行。

> 未实测前档位为待定稿初值，开跑前需落定并 commit；出现数字前一律 `【待实测】`。

## 执行器 `scripts/run_r4.py` 流程

1. `--models qwen2.5:7b`；**`enforce_local_endpoint`** 强制 endpoint ∈ {127.0.0.1, localhost}，云端形态直接报错（合规锁死）
2. 构造消息：system(注入 schema) + r4 few-shot + user(序列化 evidence 包 + 要求输出 generate_report 参数 JSON)；`adapter.chat(use_tools=False)`
3. 判分 → 失败则 `feed_back_issues` 回灌重试（`--max-retry` 默认 3），**幻觉方向不因重试后改正而免于首次幻觉计数（红线）**
4. 落盘 `experiments/r4/raw/EXP-R4-001.jsonl`（只增不改）+ `.meta.json`（对齐实验登记模板：experiment_id/date/phase_item=R-4/purpose/seed/prompt_version/commit/raw_path/conclusion/anomalies/reproduce_cmd）+ `summary-EXP-R4-001.csv`
5. `--resume` 断点续跑（同 run_v1 `done_groups`）
6. `--dry-run` 预览首个用例消息不发请求

## 纪律校验

- 两脚本 `--selftest`（不联网）：case 不变量、schema 注入、parse 三形态、判据分档、本地端点强制、断点键、回灌文本
- experiment_id 唯一 `EXP-R4-<序号>`；改参数/prompt 必新开序号
- digest/seed/prompt_version/reproduce_cmd 全进 meta；原始数据只增不改
- 未测项写 `【待实测】`；脚本只自动输出实测 rate

## 风险与对策

- 7B 生成型归纳可能幻觉游离 ref → 红线单列 + 回灌闭环 + 可选动态 grammar
- think 内夹 JSON → 复用 `strip_think` 先剥后判
- ref 字符串被改 → 要求逐字引用包内 ref，judge 精确匹配
