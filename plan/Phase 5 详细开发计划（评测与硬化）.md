## 一、阶段目标与出口

### 1.1 阶段目标

> 完成 **五项硬化**：
> ① **评测硬化**——RAGAS + 双人标注一致性（Cohen's Kappa），产出全量指标报告；
> ② **可观测硬化**——Prometheus/Grafana 指标 + 日志聚合 + 告警规则；
> ③ **运维硬化**——Compose healthcheck/资源限额 + 备份恢复演练；
> ④ **安全与权限硬化**——注入/投毒/密钥/SoD/审计不可篡改全部验证；
> ⑤ **性能硬化**——端到端压测与稳定性验证。

### 1.2 阶段出口（M5.4）

| 出口物 | 判据 |
|---|---|
| 评测报告 | 全量指标达标或中间区间有处置记录 |
| 双人标注 | `Cohen's Kappa ≥ 0.7`（一致性可接受） |
| 可观测 | 指标/日志/告警三类齐备，面板可用 |
| 备份恢复 | 演练通过，**RTO/RPO 达标** |
| 安全 | 注入/投毒/密钥/SoD 回归全部通过 |
| 压测 | 目标并发下无错误率飙升；资源峰值 ≤ 24GB |
| 停止条件 | §10.4 三条逐项核对，判定是否停止扩范围 |

### 1.3 与前后阶段的关系

```
Phase 4（前端与集成）
   └─► Phase 5（本阶段：评测与硬化）
            ├─► Phase 6 收敛：以本阶段指标作为验收依据
```

## 五、关键模块详细设计

### 5.1 W1 · 评测体系

#### 5.1.1 RAGAS 指标

| 指标 | 含义 | 目标 |
|---|---|---|
| Faithfulness | 回答是否忠于检索上下文 | 报告值（越高越好） |
| Answer Relevancy | 回答与问题相关性 | 报告值 |
| Context Precision | 检索上下文精确度 | 报告值 |
| Context Recall | 检索上下文召回覆盖 | 报告值 |

#### 5.1.2 双人标注与一致性

```
标注者 A：主标注（Phase 0/2 产出）
标注者 B：第二标注（本阶段新增）
样本：50 条评测集 + 30 条诊断结论（引用正确性）
一致性：Cohen's Kappa
  κ = (Po - Pe) / (1 - Pe)
  判据：κ ≥ 0.7 可接受；0.4–0.7 需复核争议项；< 0.4 标注规范需重订
```

**争议处置**：κ 不达标时对争议项逐条复核，修订 `labeling-spec-v1.md` 并记录（体现方法论严谨性）。

#### 5.1.3 幻觉率（3 级评分）

| 级别 | 定义 | 判为幻觉 |
|---|---|---|
| A 充分依据 | 每条结论均可溯源到证据 | 否 |
| B 部分依据 | 主结论有依据，细节有外推 | 否（记警告） |
| C 无依据 | 存在无法溯源的结论 | **是** |

```
幻觉率 = C 级数量 / 总数  → 目标 ≤ 10%
```

### 5.2 W2 · 可观测性

#### 5.2.1 指标清单

| 类别 | 指标 |
|---|---|
| 检索 | 各通道耗时、`Recall@5`（离线）、缓存命中率 |
| 推理 | 节点耗时 P95、`think` token 占比、首次成功率（在线抽样） |
| 路由 | 云端升级率、降级率、预算消耗 |
| 审核 | 审核覆盖率、平均审核时长、超时次数 |
| 存储 | 对账差异数、Milvus/Neo4j 写入失败数 |
| 资源 | 容器内存峰值、GPU 显存峰值、Redis 内存与 key 数 |

#### 5.2.2 告警规则

| 规则 | 阈值 | 级别 |
|---|---|---|
| Redis 内存 | > 80% 上限 | Critical |
| GPU 显存 | > 90% | Warning |
| 对账差异 | > 0 | Critical |
| 审核超时 | 存在 4h 未审 | Warning |
| 云端预算 | > 80% 日预算 | Warning |
| checkpoint key 数 | 异常增长 | Warning |

### 5.3 W3 · 运维硬化

#### 5.3.1 Compose 硬化要点

- 全服务 `healthcheck`（探针区分 `start_period`）；
- `depends_on: condition: service_healthy` 明确启动顺序；
- `mem_limit` / `cpus` 防单服务拖垮整机；
- `restart: unless-stopped`；
- Redis：`--maxmemory 1gb --maxmemory-policy noeviction --appendonly yes`。

#### 5.3.2 备份与恢复

| 对象 | 方式 | 频率 | 演练 |
|---|---|---|---|
| PostgreSQL（权威源） | `pg_dump` + WAL 归档 | 每日全量 | 全量恢复 + 校验行数 |
| Milvus 卷 | 卷快照 | 每周 | 挂载恢复 + 检索抽检 |
| Neo4j | `neo4j-admin dump` | 每周 | 载入恢复 + 路径查询 |
| 原始语料 | 冷备 | 变更即备 | 校验 checksum |

**目标**：记录实测 **RTO**（恢复耗时）与 **RPO**（数据丢失窗口）。

### 5.4 W4 · 安全与权限硬化

| 检查项 | 验证方式 | 期望 |
|---|---|---|
| Prompt 注入 | 10 条恶意输入样本 | 全部被净化/拒绝，不越权调用工具 |
| 工具白名单 | 尝试调用未授权工具 | 被拒并审计 |
| 高风险判定 | 构造含"停机/高压/动火"等输入 | 确定性规则命中，**不依赖 LLM** |
| 审计不可篡改 | 直接 `UPDATE audit_logs` | 触发器拒绝 |
| SoD | 提交者自审 | 前后端双重拒绝 |
| 密钥托管 | 检查代码库无明文密钥 | 仅环境变量/密钥管理 |
| 限流 | 高频调用云端接口 | 触发限流并记录 |
| 预算熔断 | 模拟超预算 | 熔断并走本地降级 |

### 5.5 W5 · 性能硬化

#### 5.5.1 压测设计

| 档位 | 并发 | 关注 |
|---|---|---|
| 基线 | 1 | 延迟分位 |
| 常规 | 10 | 错误率、P95 |
| 峰值 | 20 | 资源峰值、队列 |
| 极限 | 50 | 降级是否触发、是否雪崩 |

**指标**：错误率、P50/P95/P99、资源峰值（内存/显存/CPU）、稳定性（30min 无泄漏）。

#### 5.5.2 稳定性校验

- 连续运行 30 分钟，观察内存/显存是否单调增长（识别泄漏）；
- checkpoint 数量增长曲线；
- Redis key 增长与清理是否平衡。

## 七、验收标准与门禁

### 7.1 全量指标（最终验收口径）

| 指标 | 目标 | 结果 |
|---|---|---|
| `Recall@5` | ≥ 85% | ☐ |
| `MRR` | ≥ 0.75 | ☐ |
| `NDCG@5` | 报告值 | ☐ |
| 引用正确率 | ≥ 90% | ☐ |
| **幻觉率** | **≤ 10%** | ☐ |
| 工具调用首次成功率 | ≥ 90% | ☐ |
| `P95 检索` | < 800ms | ☐ |
| `P95 端到端`（本地路径） | < 3s | ☐ |
| 置信度 ECE | ≤ 0.10 | ☐ |
| 高风险审核覆盖率 | 100% | ☐ |
| Cohen's Kappa | ≥ 0.7 | ☐ |
| 资源峰值 | ≤ 24GB | ☐ |

> **口径声明**：所有指标基于**模拟数据的初步验证**，须在报告中显式声明局限；`P95 端到端` 仅统计**本地命中路径**，云端升级单独统计。

### 7.2 门禁判定

| 情况 | 处置 |
|---|---|
| 全项达标 | **M5.4 通过**，进入 Phase 6 |
| 幻觉率 10–15% | 中间区间：加强引用强制；记录处置与代价 |
| `P95` 3–4s | 中间区间：缓存优化 + 降低升级率；记录权衡 |
| κ 0.4–0.7 | 复核争议项 + 修订标注规范；允许有条件通过 |
| **对账差异 > 0** | **阻塞**：数据一致性缺陷，必须修复 |
| **审计可被修改** | **阻塞**：安全缺陷，必须修复 |
| 资源峰值 > 28GB | **阻塞**：触发降级映射并调整 MVP |

### 7.3 停止条件核对（V5.0 §10.4）

| # | 停止条件 | 核对 |
|---|---|---|
| 1 | Must 链 **13 项**端到端可演示（一次完整跑通告警→报告→审核） | ☐ |
| 2 | **≥3 项量化指标达标**：`Recall@5 ≥85%` + `P95 检索 <800ms` + 工具首次成功率 ≥90% | ☐ |
| 3 | 版本锁定清单 + 风险登记册**定稿** | ☐ |

> **三条同时满足 → 停止扩展范围，转入 Phase 6 收敛交付。**
