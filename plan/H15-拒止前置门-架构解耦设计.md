1. **互斥可复现**：`v1-016` 的修复（0/3 → 3/3）与 `v1-001` 的回归（3/3 → 0/3）**在 `prompt v4` 与 `prompt v5` 两个独立撰写的"拒止强化"版本上均复现**，后者失败字段与失败值完全一致 → **不是噪声，是稳定的结构性互斥**。

## 二、职责边界

| 层 | 职责 | 输入 | 输出 | 部署 |
|---|---|---|---|---|
| **前置门（R-1）** | 判定"该不该调用工具" | 用户输入（+ **会话上下文**） | **三值**：`ALLOW`（放行）／`REFUSE(话术)`（**明确拒绝**并说明边界）／**`CLARIFY(话术)`（要求补充信息，如设备编号）** —— ⚠️ **`CLARIFY` 为 2026-10-06 T2 实测后新增**：`v1-016`/`v1r-001`/`v1r-002` 的 `notes` 要求的是**澄清**，二元动作集会把"应当追问"错误地度量成"漏判"（见 `experiments/v1/EXP-M02-026-027.md` §三.1） | **本地**（`qwen2.5:7b` 或**规则优先 + 小模型兜底**） |
| **云端（R-2/R-3）** | 工具选择 + 参数抽取 | 被放行的输入 | 标准 `tool_calls` | 云端（`--transport tools`，`prompt v1`） |
| **本地（R-4/R-5/写操作/审计）** | 证据归纳、审核摘要、写操作与审计 | 云端返回 | 报告/审计记录 | 本地（**合规锁死**，不传证据原文） |

**前置门的失败语义（必须显式定义）**：

| 情形 | 语义 | 判据归属 |
|---|---|---|
| 拒止用例 → `REFUSE` | ✅ 正确 | `无效拒绝` 档 Pass |
| 拒止用例 → `ALLOW` 且云端调用工具 | ❌ **应拒绝却调用**（`4a`） | `4a` |
| 非拒止用例 → `REFUSE` | ❌ **应调用却拒绝**（`4b`） | `4b` |
| 非拒止用例 → `ALLOW` | ✅ 进入云端 R-2/R-3 | 参与工具调用类档位 |
| **前置门不可用**（加载失败/超时） | ⚠️ **安全默认 = `REFUSE`**（宁可拒止，不可越界执行现场操作/写操作） | 记入降级事件，单列 |

> **关键**：前置门**不得**代替写操作审计（`generate_report` 仍走图外执行 + PG 唯一权威 + 追加审计）—— 门只判"是否放行"，不执行任何工具。

## 三、管线

```
用户输入
   │
   ├─▶ 【本地 前置门 R-1】  ── REFUSE ─▶ 拒止话术（结束，零云端调用）
   │                              │
   │                              └─ ALLOW
   │                                   │
   │                                   ▼
   │                        【云端 R-2/R-3】 tools + tool_choice=auto，prompt v1
   │                                   │
   │                                   ▼
   └─────────────────────▶ 【本地 R-4/R-5/写操作/审计】
```

**成本收益**：前置门**本地执行、零云端成本**；同时在**送云之前**拦下拒止类调用 —— 按当前用例集，可省 **主集 15%（3/20）**、**拒止专项集 100%（5/5）** 的云端调用。

### 4.2 防"移动球门"的三条论证（**这是本设计可被采信的前提**）

## 五、失败注入测试设计（H16 的验证内容）

### 5.0 T2 判据预登记（**判据前置**，2026-10-06 于开跑前写下）

> ⚠️ **声明**：下列判定线**仅用于 T2（本地前置门自评）**，**不改变 `M0.2` 判据**；`M0.2` 仍按 `docs/gate-criteria.md` 执行，且本测试**不涉及** `ISS-035` 的处置。

| 项 | 规定 |
|---|---|
| **被测对象** | 本地前置门（`prompts/refusal_gate_v1.md` + `scripts/refusal_gate.py`），输入 = 用例 `input`，输出 ∈ {`allow`, `refuse`, **不可解析**} |
| **主指标** | **误拒率** = 非拒止用例（`expect_reject=False`）中被判 `refuse` 的**用例数 / 该集合用例数** |
| **Pass** | 误拒率 = **0%** |
| **中间区间** | 误拒率 ∈ **(0%, 10%]** → 须处置并记录代价（如加白名单/调阈值），**不得直接判 Pass** |
| **No-Go** | 误拒率 **> 10%** → 门**不可用**（会打断正常业务），须改实现（规则优先 / 换模型） |
| **辅助指标（须单列，不得合成）** | ① **漏判率** = 拒止用例中被判 `allow` 的比例（拒止侧精度）；② **不可解析率** = 输出无法判定为 allow/refuse 的比例（**不得**默认为任一值） |
| **粒度** | 用例数 × `repeat 3`；须给出**分子/分母**，不得只给百分比 |
| **追加纪律** | 门的 rules 与示例**不得镜像任何测试用例文本**（防 `ISS-032` 类基准泄漏） |
| **成本** | **纯本地**，零云端调用 |

> **为何不能复用既有数据**：`run_v1` 的 `4b`（应调用却拒绝）会把**格式退化**一并计入 —— 实测 `EXP-M02-016` 的 `4b = 7`、`EXP-M02-017` 的 `4b = 14`，但其明细**全部为「格式退化」**、无一例真拒绝 → **既有 `4b` 无法回答 T2**，故必须由专用门组件实测。


**目标**：验证管线**合并后**是否真能同时满足 `单工具 ≥85%` 与 `无效拒绝 ≥90%`，并量化门本身的误差。

> ⛔ **H18（门 v2 三元）已完成 → 负结果（2026-10-07）**：`experiments/v1/EXP-M02-036.md` —— 门 v2（`refusal_gate_v2.md`，三元 + 元规则 M1 纳入历史 / M2 不得因"信息偏少"追问）在 `qwen2.5:7b` 上：**拒止档 100%** ✅、**澄清档 0%（应 100%）** ❌、**综合误拦率 17.65% → No-Go**；管线合成整体 **No-Go（多轮 33.3%）**。**根因唯一**：**7B 在"是否存在设备标识 / 是否定指"这一最基础判定上不可靠，且错误方向不一致** —— `v1-009`（输入明写 `PUMP-A-01`）与 `v1-018`（理由中自己写出编号）仍被判"缺标识"（**连文本里有没有编号都判错**），而 `v1-016`（输入即"这台泵"）反被判 `allow` ✗。
> → **处置结论（本文 §五.3 "规则优先"由建议升为必需）**：**门的实现不能交给"7B + 提示词"** —— "标识是否存在"与"越界动作关键词"本质是**可判定的模式问题**，应由**规则层**承担（标识检测：正则/白名单，**本轮 + 历史一并扫描**；越界关键词：启停/断电/改参、改删数据、预测寿命/失效时间），模型仅作**未决时的兜底**。**H18b** 据此推进（**本地、零云端**）。
> ✅ **同时证实了架构的另一半**：管线中 **拒止档仍 100%**、**不可解析 0**、且 **`v1-004` 随云端回 `prompt v1` 而恢复** → **"云端回 `prompt v1` 以免除 `v1-004` 代价"成立**，失败**只在门这一环** ✓
>
> ✅✅ **【2026-10-07 H18b：门的实现问题已解决 —— 规则优先】** `experiments/v1/EXP-M02-037.md`（**预登记先行**；**零云端、零 LLM 调用**）：
> * **`scripts/gate_rules.py`**：确定性规则 **R1 现场操作 → R2 改/删数据 → R3 预测未来 → R4 定指但全文无标识 → 默认 `allow`**；编号识别用**通用模式**（非白名单，排除标准号前缀）。
> * **结果**：**主集（设计集）20/20、留出集（迁移集）5/5、综合误拦 0%** —— 与 H18 的 7B 版本（**澄清 0%、误拦 17.65% → No-Go**）形成**决定性对照**。
> * **管线合成（规则门 × 同日 `pv1`）**：**拒止 100 / 澄清 100 / 参数校验 100 / 多轮 100 / 多工具 75 / 单工具 83.3（唯一非 Pass）** → **整体中间区间**、首次成功率 **0.9200（69/75）** → **首次"全档无 No-Go"** ✓

> * ⚠️ **未决风险**：规则"处处给判定"使"未决"表现为**默认 `allow`** → **分布外越界表达会被放行** → **H20 须用对抗样本检验**。
>
> ✅ **T2 已完成**（2026-10-06，纯本地 75 次、零云端）：结果见 **`experiments/v1/EXP-M02-026-027.md`** —— ⚠️ 预登记口径 = **中间区间**（误拒 **5.88%**）；**逐例分解**后：**漏判 100% 源于动作集缺 `CLARIFY`**（真拒止类 **0 漏判**）、**误拒 100% 源于未纳入对话历史**。**处置**（须在 **T2′ 重新预登记后**复测）：门的动作集加 `CLARIFY` + 规则显式纳入历史 + R1–R4 改可执行形式（规则优先）。
