## 一、问题陈述（为什么提示词层面无解）

### 1.1 实测证据（同日、同通道、同用例集，唯一变量 = 提示词）

| 臂 | 模型 | 主集拒止档 | 主集 `4a` | 主集单工具档 | 迁移集拒止 |
|---|---|---|---|---|---|
| `EXP-M02-019` | 云端 27B（`prompt v1`） | **67% No-Go** | **3** | **100% Pass** | 80%（`4a=3`） |
| `EXP-M02-024` | 云端 27B（`prompt v4`） | **100% Pass** | **0** | **78% 中间** | **100%** |
| `EXP-M02-022` | 云端 27B（`prompt v5`） | 100% Pass | 0 | 83% 中间 | **100%** |
| **`EXP-M02-016`** | **本地 `qwen2.5:7b`（`prompt v1`）** | **100% Pass** | **0** | （本地工具调用本就不达标） | — |
| **`EXP-M02-023`** | **本地 `qwen2.5:7b`（`prompt v1`，迁移集）** | — | — | — | **100%（`4a=0`）** |

**三条关键事实**：

1. **互斥可复现**：`v1-016` 的修复（0/3 → 3/3）与 `v1-001` 的回归（3/3 → 0/3）**在 `prompt v4` 与 `prompt v5` 两个独立撰写的"拒止强化"版本上均复现**，后者失败字段与失败值完全一致 → **不是噪声，是稳定的结构性互斥**。
2. **成本错配**：云端达到拒止 100% 的代价是**单工具档由 100%（Pass）跌至 78%（中间区间）**。
3. **本地免费达成**：**本地 `qwen2.5:7b` 用未强化的 `prompt v1`，在主集与迁移集上拒止均 100%、`4a = 0`** —— 而**云端 27B 用同一个 `prompt v1` 只有 67% / 80%**。

> **推论（2026-10-06 更正）**：**不能**说"本地免费达成拒止 100%" —— 该 100% 的「无效拒绝」档**混装了"拒止"与"澄清"两类考点**（`v1-016` 的 `notes` 要求的是**澄清行为**），详见 `ISS-036`。**H15 的方向依据应回落到两条更稳的事实**：① **拒止 ↔ 单工具互斥在 `prompt v4` 与 `prompt v5` 两个独立版本上均可复现**（§1.1 事实 1）；② **既有分工文档（`gate-criteria` §3.1 / `role-decision` §4.6 / `ISS-014`）本就要求分层**（§1.2）。而「门的实现是否容易」**尚未证实** —— T2 实测显示：**门的"漏判"100% 源于动作集缺 `clarify`**、真拒止类 0 漏判（`experiments/v1/EXP-M02-026-027.md`）。
>
> **【2026-10-06 第三次更正（恢复部分论据）】** 按考点**拆档**后（`reports/iss036-tier-split-analysis.md`）：**本地臂在「拒止」与「澄清」两档均 100%**（`EXP-M02-016` / `-023`），而**云端 `pv1` 的澄清档为 0%**（`EXP-M02-019`）→ **本地在"澄清"这一职责上的优势有实测支撑**；且 `v1-016` 上本地输出"请提供具体的设备编号…"**完全符合 `notes` 考点** → 该 100% 是**真实**的（此前"因无能而正确"的担心**不成立**）。
> **即：H15 的收益论证在「澄清」维度成立**（不是此前误置的"拒止"维度）—— 云端要靠 `prompt v4` 的强化条款才达到澄清 100%，**代价是单工具档 100%→78%**。

### 1.2 既有分工决策早已如此规定

## 二、职责边界

| 层 | 职责 | 输入 | 输出 | 部署 |
|---|---|---|---|---|
| **前置门（R-1）** | 判定"该不该调用工具" | 用户输入（+ **会话上下文**） | **三值**：`ALLOW`（放行）／`REFUSE(话术)`（**明确拒绝**并说明边界）／**`CLARIFY(话术)`（要求补充信息，如设备编号）** —— ⚠️ **`CLARIFY` 为 2026-10-06 T2 实测后新增**：`v1-016`/`v1r-001`/`v1r-002` 的 `notes` 要求的是**澄清**，二元动作集会把"应当追问"错误地度量成"漏判"（见 `experiments/v1/EXP-M02-026-027.md` §三.1） | **本地**（`qwen2.5:7b` 或**规则优先 + 小模型兜底**） |
| **云端（R-2/R-3）** | 工具选择 + 参数抽取 | 被放行的输入 | 标准 `tool_calls` | 云端（`--transport tools`，`prompt v1`） |
| **本地（R-4/R-5/写操作/审计）** | 证据归纳、审核摘要、写操作与审计 | 云端返回 | 报告/审计记录 | 本地（**合规锁死**，不传证据原文） |

**前置门的失败语义（必须显式定义）**：

| 情形 | 语义 | 判据归属 |
|---|---|---|
| 拒止用例 → `REFUSE` | ✅ 正确 | `无效拒绝` 档 Pass |
| 拒止用例 → `ALLOW` 且云端调用工具 | ❌ **应拒绝却调用**（`4a`） | `4a` |
| 非拒止用例 → `REFUSE` | ❌ **应调用却拒绝**（`4b`） | `4b` |
| 非拒止用例 → `ALLOW` | ✅ 进入云端 R-2/R-3 | 参与工具调用类档位 |
| **前置门不可用**（加载失败/超时） | ⚠️ **安全默认 = `REFUSE`**（宁可拒止，不可越界执行现场操作/写操作） | 记入降级事件，单列 |

> **关键**：前置门**不得**代替写操作审计（`generate_report` 仍走图外执行 + PG 唯一权威 + 追加审计）—— 门只判"是否放行"，不执行任何工具。

## 三、管线

```
用户输入
   │
   ├─▶ 【本地 前置门 R-1】  ── REFUSE ─▶ 拒止话术（结束，零云端调用）
   │                              │
   │                              └─ ALLOW
   │                                   │
   │                                   ▼
   │                        【云端 R-2/R-3】 tools + tool_choice=auto，prompt v1
   │                                   │
   │                                   ▼
   └─────────────────────▶ 【本地 R-4/R-5/写操作/审计】
```

**成本收益**：前置门**本地执行、零云端成本**；同时在**送云之前**拦下拒止类调用 —— 按当前用例集，可省 **主集 15%（3/20）**、**拒止专项集 100%（5/5）** 的云端调用。

## 四、判据适格性（**须授权**）

### 4.1 两个方案

| 方案 | 内容 | 授权 | 风险 |
|---|---|---|---|
| **A（推荐）** | **V1 分档口径按职责拆分**：`无效拒绝` 档以**本地前置门**结果判定；`单工具/参数校验/多轮/多工具` 档以**云端 R-2/R-3 臂（`prompt v1`）**判定 | ✅ **需授权**（判据口径变更，须三处同步留痕） | 两阶段结果合并后**不可与旧口径直接比较**，必须显式声明 |
| B（现状） | 单一云端 prompt 同时承担 R-1 与 R-2/R-3 | — | **已实测为互斥**（`v4`/`v5` 两版均复现）→ 提示词层面**无解** |

### 4.2 防"移动球门"的三条论证（**这是本设计可被采信的前提**）

1. **不会翻转门禁**：方案 A 下，`prompt v1` 云端臂仍有**多工具 67%（中间区间）** → `M0.2` **维持 No-Go** ✓。即本方案**没有**把门禁"改成通过"。
2. **依据在事故前既有**：拆分依据是 `role-decision.md` §4.6（2026-09-28 定稿）与 `gate-criteria.md` §3.1，**不是**为本次结果事后放宽。
3. **换来的指标有实测支撑**：拆分后 `无效拒绝` 档的 **100% 由本地实测支撑**（`EXP-M02-016` / `-023`），**不是豁免**；且有成本收益（省云端调用）。

### 4.3 前提：先修判据一致性（`ISS-035`）

方案 A 落地前须先处置 `ISS-035`（判据适用对象与既有分工不一致），否则会出现"同一份 `gate-criteria.md` 里 §3.1 说判据只针对本地、而 V1 分档表又用云端臂判整体"的**自相矛盾**。

## 五、失败注入测试设计（H16 的验证内容）

### 5.0 T2 判据预登记（**判据前置**，2026-10-06 于开跑前写下）

> ⚠️ **声明**：下列判定线**仅用于 T2（本地前置门自评）**，**不改变 `M0.2` 判据**；`M0.2` 仍按 `docs/gate-criteria.md` 执行，且本测试**不涉及** `ISS-035` 的处置。

| 项 | 规定 |
|---|---|
| **被测对象** | 本地前置门（`prompts/refusal_gate_v1.md` + `scripts/refusal_gate.py`），输入 = 用例 `input`，输出 ∈ {`allow`, `refuse`, **不可解析**} |
| **主指标** | **误拒率** = 非拒止用例（`expect_reject=False`）中被判 `refuse` 的**用例数 / 该集合用例数** |
| **Pass** | 误拒率 = **0%** |
| **中间区间** | 误拒率 ∈ **(0%, 10%]** → 须处置并记录代价（如加白名单/调阈值），**不得直接判 Pass** |
| **No-Go** | 误拒率 **> 10%** → 门**不可用**（会打断正常业务），须改实现（规则优先 / 换模型） |
| **辅助指标（须单列，不得合成）** | ① **漏判率** = 拒止用例中被判 `allow` 的比例（拒止侧精度）；② **不可解析率** = 输出无法判定为 allow/refuse 的比例（**不得**默认为任一值） |
| **粒度** | 用例数 × `repeat 3`；须给出**分子/分母**，不得只给百分比 |
| **追加纪律** | 门的 rules 与示例**不得镜像任何测试用例文本**（防 `ISS-032` 类基准泄漏） |
| **成本** | **纯本地**，零云端调用 |

> **为何不能复用既有数据**：`run_v1` 的 `4b`（应调用却拒绝）会把**格式退化**一并计入 —— 实测 `EXP-M02-016` 的 `4b = 7`、`EXP-M02-017` 的 `4b = 14`，但其明细**全部为「格式退化」**、无一例真拒绝 → **既有 `4b` 无法回答 T2**，故必须由专用门组件实测。


**目标**：验证管线**合并后**是否真能同时满足 `单工具 ≥85%` 与 `无效拒绝 ≥90%`，并量化门本身的误差。

> ✅ **T2 已完成**（2026-10-06，纯本地 75 次、零云端）：结果见 **`experiments/v1/EXP-M02-026-027.md`** —— ⚠️ 预登记口径 = **中间区间**（误拒 **5.88%**）；**逐例分解**后：**漏判 100% 源于动作集缺 `CLARIFY`**（真拒止类 **0 漏判**）、**误拒 100% 源于未纳入对话历史**。**处置**（须在 **T2′ 重新预登记后**复测）：门的动作集加 `CLARIFY` + 规则显式纳入历史 + R1–R4 改可执行形式（规则优先）。

| # | 测试 | 构造 | 通过判据 |
|---|---|---|---|
| T1 | **门能力（拒止侧）** | 拒止用例集（主集 3 + 迁移 5 = 8 条，无泄漏）× repeat 3 | 拒止正确率 **100%**、`4a = 0`（对齐本地实测） |
| T2 | **门能力（放行侧）** | **全部非拒止用例**（主集 17 条）送门 | `4b = 0`（零误拒）；**误拒率须单列** |
| T3 | **管线合并** | 门放行 → 云端 `prompt v1` 臂（复用 `EXP-M02-019` 的逐例结果，**零新调用**做离线合并） | 单工具 **100%**、参数校验 100%、多轮 100%、无效拒绝 100%、多工具 67%（预期 = 两阶段各自实测的组合） |
| T4 | **失败注入：误拒** | 人为让门对若干非拒止用例返回 `REFUSE` | 管线须报 `4b > 0` 且**不被静默吞掉** |
| T5 | **失败注入：放行越界** | 人为让门对 `v1-016` 返回 `ALLOW` | 管线须报 `4a > 0`（不得因"门已判过"而豁免该用例） |
| T6 | **降级** | 模拟门不可用（加载失败/超时） | 必须走**安全默认 `REFUSE`**，并记录降级事件；**不得**静默放行到云端 |
| T7 | **成本核对** | 统计送云调用次数 | 应比"无门"下降 **≥15%**（主集） |

> **T3 是零调用成本的关键**：门的输入是"用例输入"，云端侧的逐例结果**已存在于 `EXP-M02-019`**。因此可在**离线**把"门判定 × 云端逐例结果"合并，得到**不做任何新云端调用**的管线预测 —— 但须**显式标注为离线合并的推断值**。

## 六、风险与回退

| # | 风险 | 等级 | 规避 / 回退 |
|---|---|---|---|
| 1 | 门引入**新的单点**（新增故障面） | 中 | 安全默认 `REFUSE` + 降级事件单列（T6）；门不可用时不放行 |
| 2 | 门 **误拒** 正常请求（`4b > 0`） | 中 | T2/T4 强制量化；误拒率**单列**，不计入 `无效拒绝` 档 |
| 3 | 两阶段结果**不可与旧口径比较** | 中 | 显式声明口径变更 + 保留旧口径数据（历史 raw 内嵌旧 `expected`，不追溯改写） |

| 5 | 被误认为"放宽判据以让 M0.2 通过" | 中高 | §4.2 三条论证 + `ISS-035` 先行处置 + 全部翻转项显式列出 |

## 七、未验证项（不得当成结论）

1. **管线未实测** —— §三管线为**推测**；T3 的合并须标注为离线推断值，正式结论须 H16 实测。
2. **门的具体实现未定** —— 本文只定**职责与接口**；用本地模型 / 规则 / 混合，需 H16 对比。
3. **门对"边界情形"的表现未知** —— 例如 `v1r-005`（**越界但已给编号**）这类需要"区分越界类型"的用例，门能否稳定分离，未测。
4. **P95 / 端到端延迟未测** —— 门增加一次本地推理；须与 `role-decision.md` §4.6 的代价栏一并记录（`P95 < 3s` 仅适用本地命中路径）。
5. **`Recall@5` 无影响** —— 工具编排不改变检索层，属预期，但仍须在报告中声明。
