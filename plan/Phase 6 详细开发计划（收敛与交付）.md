### 5.3 演示脚本（主场景）

```
场景：离心泵驱动端轴承振动异常

Step 1  制造告警：脚本注入 vibration=6.2 mm/s（超阈值）
Step 2  触发：告警去重 → LangGraph 启动，前端实时显示节点进度
Step 3  分析：query_sensor 展示振动趋势与温度相关性
Step 4  检索：证据卡片展开——手册段落 + 历史工单 + 图谱路径（轴承磨损→润滑不足→温升）
Step 5  推理：输出根因与建议，展示置信度 breakdown（为何这样判断）
Step 6  审核：建议含"停机更换"→ risk=HIGH → interrupt，审核界面弹出
Step 7  裁决：审核人查看证据 → 通过 → 报告正式发布（幂等）
Step 8  追溯：报告内每条结论可点回原文；Trace 时间线展示全链路耗时
```

**备用场景（应对提问）**：

| 场景 | 演示点 |
|---|---|
| 低置信降级 | 输出"初步判断，建议人工确认"，显式标注降级原因 |
| 云端不可用 | 离线降级路径可用 |
| 断网演示 | 本地闭环仍可运行（本地优先的价值） |
| 自审拦截 | 提交者本人无法审核自己的报告 |

### 5.5 Q&A 预演（针对最易被追问的点）

| 问题 | 应答要点 |
|---|---|
| 为什么用 7B 而不是大模型？ | 合规刚性（数据不出厂）+ 8GB 显存硬约束；用双模型分工扬长避短；云端兜底保证质量上界 |
| 本地模型工具调用可靠吗？ | Phase 0 V1 实测数据支撑；`qwen2.5:7b` 原生 FC；70–90% 有明确处置策略 |
| 置信度 0.75 哪来的？ | 复合公式 + 温度缩放校准 + `ECE ≤0.10`；阈值由"自动出报告所需精确率"反推，非拍脑袋 |
| 三存储数据不一致怎么办？ | Outbox + 补偿队列 + 每日对账；PG 为唯一权威源；失败注入测试验证 |
| 大模型幻觉如何控制？ | 引用强制（无来源不出结论）+ 高风险人工审核 + 降级显式化；幻觉率实测 ≤10% |
| 为什么不用 MongoDB？ | 业务库需强事务/复杂 JOIN/审计不可篡改，恰是 MongoDB 弱项；灵活字段用 JSONB |
| 为什么现在才引入 Nginx？ | 开发期直接暴露端口更简单；生产化才需要统一入口 + WS 透传 + SSL，避免过早复杂化 |
| 项目规模与工期？ | Phase 0 十天标定，总计约 100 工作日；已用停止条件控制范围，避免"永远做不完" |
| 单人如何保证评测可信？ | 双人标注 + Cohen's Kappa + 显式声明"基于模拟数据的初步验证" |
| 哪些没做？ | 多租户/微调/移动端/真实 Modbus-OPC UA 直连/自动执行维修——**明确边界并区分"不做"与"预留接口"** |
