## 〇、结论先行

1. **处置链 ①②③④ 已全部执行仍 No-Go**，加上 P5/P6/P7 与 F1–F6 复审，**共 9 条已试路径全部未能破局**（§三）。
2. **两条结构性结论已确证**：
   - **"换更大模型"不是破局手段** —— 云端 27B（`Qwen/Qwen3.8-27B`）首次成功率仅 **0.60**，低于本地最优 **0.68**（`EXP-V1-010` qwen）；模型规模不是瓶颈。

5. **推荐顺序（§七）**：先清剩余**口径/输入侧确定性缺陷**（零或低模型成本）→ 再做**单工具档专项** → 架构侧维持"R-2/R-3 上云"但不宣称 Pass → **不建议**换更大模型 / 用例集重构 / 微调。
6. **战略备选（§七.4，必须一并评估）**：接受首次成功率 No-Go，**用"校验回灌重试 + 低置信度降级 + 高风险人工审核"做工程兜底**——重试后成功率实测已达 **0.90–1.00**（`EXP-V1-003/007/010`），这是**不改判据**前提下可达成的产品路径。
7. ⚠️ **重要更正（本文件补充，2026-09-30）**：§五 对 **U6「换/加更强模型」** 的原判「不建议」**依据不充分，已上调为「条件性推荐」**——因为 **`EXP-M02-001`（云端 0.60）是在 `tools_v2` + `prompt v1`（schema 无测点目录）下测的**，属"题目缺条件"的旧口径；而 **F2 采纳的 `tools_v4` 修复从未在云端验证过**（仅在本地 7B 上验证 +28pp：0.4667→0.7500）。→ **详见 §九 专项分析**。

## 一、破局的定义与判据基线

**破局 = M0.2 解除 = 整体档位翻为 Pass**（不是"某个指标变好"）。

| 类型 | pass 线 | 中间区间 | No-Go → 处置 |
|---|---|---|---|
| 单工具 | **≥85%** | 70–85% | <70% → 云端工具调用转正 |
| 参数校验 | **≥85%** | 70–85% | <70% → 云端工具调用转正 |
| 多轮 | **≥85%** | 70–85% | <70% → 云端工具调用转正 |
| 无效拒绝 | **≥90%** | 70–90% | <70% → 云端工具调用转正 |
| 多工具 | **≥70%** | 50–70% | <50% → 架构切分 |

> **整体合成规则**：整体 = 有数据类型的**最差档位**。任一档 No-Go → 整体 No-Go。
> **判据对象**：均为**首次成功率**（第 1 次即全对）；重试后成功率仅作辅助。
>
> ⚠️ **破局的硬约束（不可绕过）**：**不改阈值、不删用例、不"移动球门"**（`reports/v1-review-v3.md` §八）。因此任何"通过放宽判据达成"的方案都**不构成破局**。

## 二、破局起点：现状基线（各档最优值）

> 口径：取**各档迄今最佳实测**，不跨类型混算。

| 档 | pass 线 | 本地最优 | 云端最优 | 最佳配置来源 | 状态（距线） |
|---|---|---|---|---|---|
| **单工具** | ≥85% | **67%**（ds）/ 57%（qwen） | 67%（27B） | `EXP-V1-010`；四臂 C 亦 67% | ❌ **−18pp** |
| **参数校验** | ≥85% | **100%**（qwen） | 75%（27B） | `EXP-V1-010`（ISS-024 修复后） | ✅ **本地已 Pass** |
| **多轮** | ≥85% | **75%**（ds） | 33%（27B） | `EXP-V1-010`；F4/F6 重判后多处翻 Pass | ⚠️ −10pp（中间区间） |
| **无效拒绝** | ≥90% | **100%**（qwen，prompt v2 + 拒止示例） | 67%（27B） | `EXP-V1-004`；四臂 C 亦 9/9 | ✅ 本地可 Pass（但**提示词条件化**，`ISS-026`） |
| **多工具** | ≥70% | **40%**（qwen） | 50%（27B） | `EXP-V1-010` / `EXP-M02-001`（集合覆盖 1.00） | ❌ **−30pp / −20pp** |

**读法**：
- **参数校验**：ISS-024 修复（few-shot 真生效）后 qwen 已达 **100% → 该档已 Pass**；说明"few-shot 真生效"是**已验证的正收益**（qwen 参数校验 80%→100%、多工具 20%→40%）。
- **多轮**：本地 ds 达 75%（中间区间），叠加 F4/F6 判据修正后多处翻 Pass → **可达成**。
- **无效拒绝**：本地 qwen 在**含拒止示例的 prompt v2** 下 100%；但换回 prompt v1 即掉到 0（四臂 A/D）→ 属**提示词条件化**而非稳定能力（`ISS-026`）。
- **单工具 / 多工具**：**两条真实短板**，且**任何已试路径均未越过** → 是 M0.2 的实际"地板"。

**重试后成功率（工程兜底潜力）**

| 实验 | qwen 重试后 | ds 重试后 |
|---|---|---|
| `EXP-V1-003`（约束解码全量） | **0.95** | 0.90 |
| `EXP-V1-007`（工具Schema v2, 25 例） | **0.96** | 0.92 |
| `EXP-V1-010`（ISS-024 修复基准） | **1.00** | 0.92 |

> 即：**校验错误回灌重试**可把任务级成功率拉到 **0.90–1.00**，但**首次成功率**仍低 → 这是"判据 No-Go 与产品可用性解耦"的关键事实（§七.4）。

## 九、专项分析：更换云端模型（`deepseek-ai/DeepSeek-V4.1-Flash`）能否破局

### 9.1 先纠正一个前提：现有"云端 0.60"是**题目缺条件**下的成绩

| 项 | `EXP-M02-001`（2026-09-30 13:46） | F2 采纳形态（`tools_v4`，2026-09-30 14:20 之后产生） |
|---|---|---|
| Schema | **`tools_v2`** —— `sensor_ids` 仅举例 `PUMP-A-01.vib_x` | **`tools_v4`** —— 内嵌 **5 个规范测点目录** + 轴向/驱动端映射 |
| prompt | `tool_call_prompt_v1.md` | 同（F2 采纳形态 = 只补 schema、保留 prompt v1） |
| 实测结果 | 云端 27B 首次 **0.60** | **云端从未验证** |

> **改动范围经实测比对**：`tools_v4` 相对 `tools_v2` **仅扩写 `query_sensor.sensor_ids` 的 `description`**（+版本元数据），**未改动任何 `items` / `enum` / `required` / 结构** → **判分语义不变**，可作干净对照。
> **该修复在本地 7B 上已验证**：`EXP-M02-002` 臂 A 0.4667 → **臂 C 0.7500（+28.3pp）**，机制修复 9/9 稳定（`temp_drive`→`temp_bearing_de`）。
> **而 `EXP-M02-001` 的 8 条失败中，v1-005 / v1-010 / v1-013 三条正是该"任务信息不足"类**（`reports/v1-review-v3.md` §二）→ 云端 0.60 **系统性低估**了当前采纳形态的能力。

**推论**：现在**直接换模型 + 沿用 `tools_v2`** 测，会在**同一个缺条件的题目**上重测一次 → 大概率复现 `EXP-M02-001` 的结论，**白耗 20 次云预算**。

### 9.2 分档外推（**推测，非实测**）

| 档 | 云端 27B（`tools_v2`） | F2 补齐后（推测） | DeepSeek-V4.1-Flash（推测） | 依据 |
|---|---|---|---|---|
| 单工具 ≥85% | 67% | ↗（v1-005 属此档且为信息不足） | 中–高 | 判据修正后本地单工具**零翻转** → 含真实能力成分 |
| 参数校验 ≥85% | 75% | ↗（v1-013 属此档） | 中–高 | 同上 |
| 多轮 ≥85% | 33% | ? | 中 | 云端 27B 仅 33% |
| 无效拒绝 ≥90% | 67% | ? | 中–高 | 线最高（≥90%） |
| **多工具 ≥70%** | **50%**（集合覆盖 **1.00**） | ? | **中（关键卡点）** | 云端历史 50%；编排无问题、**卡参数值** |

### 9.3 结论

1. **单靠换模型（不补 F2）→ 大概率不过**：模型再强也**猜不出** `de/nde`、`vib_z=轴向` 这类未写入 schema 的命名约定 —— 已由 `EXP-M02-002` 臂 A/D 实证（同一批用例在缺少测点目录时系统性地写错）。
2. **换模型 + F2 → 有可能过，但不保证**：最可能落入 **0.75–0.85** 区间，**仍可能卡在多工具（≥70%）或单工具（≥85%）其中一档**。
3. **决定性变量不是模型规模**，而是**多工具档**与**单工具档**；因此换模型**不能替代 U1（单工具档专项）**。
